# Task 6.6 - Módulos ativos no frontend e menu filtrado

## Objetivo

Compartilhar os módulos ativos com o frontend e esconder do menu o que o tenant não tem, com convite ao plano superior.

## Tipo

frontend-componente

## Arquivos a criar/modificar

- `app/Http/Middleware/HandleInertiaRequests.php` -> modificar (compartilhar `modulos`)
- `resources/js/Composables/useModulos.js` -> criar
- `resources/js/Components/Sidebar.vue` -> modificar

## Contexto necessário (ler antes)

- `app/Services/ModuleService.php` -> `ativosPara()`
- `resources/js/Components/Sidebar.vue` -> navegação atual, já filtrada por permissão no Plano 2 (Task 2.10)
- `resources/js/Composables/useMasks.js` -> padrão de composable do projeto
- `.claude/skills/frontend-design-system/SKILL.md` -> padrões visuais

## Skills necessárias

- `frontend-design-system`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

1. Em `HandleInertiaRequests::share()`, acrescentar `modulos` com o array de chaves ativas do tenant do usuário.

2. `useModulos.js`, no mesmo espírito do composable de permissões do Plano 2:
   - `temModulo(chave): boolean`
   - `modulos`: computed com a lista

3. Em `Sidebar.vue`, cada item de menu de módulo controlável ganha a verificação combinada: aparece se o usuário tiver a permissão **e** o tenant tiver o módulo. A verificação de permissão já existe (Task 2.10); esta acrescenta a de módulo.

4. Item de módulo indisponível **some** do menu. Deixar visível e desabilitado, com cadeado, virou padrão de mercado, mas para um sistema operacional diário isso adiciona ruído permanente. Decisão: esconder, e concentrar o convite comercial na página de módulo indisponível (Task 6.4) e na tela de plano do tenant (Plano 7).

### Regras de negócio aplicáveis

- Esconder no menu é conforto visual, não segurança. Quem barra é o middleware da Task 6.4.
- Permissão e módulo são verificações independentes: usuário com permissão em tenant sem o módulo não vê o item.
- Nada de emoji no menu; SVG inline como o restante do projeto.

### Critérios de aceitação

- [ ] `page.props.modulos` chega ao frontend com as chaves ativas
- [ ] Menu esconde Financeiro quando o tenant não tem o módulo
- [ ] Menu esconde Financeiro quando o usuário não tem a permissão, mesmo com o módulo ativo
- [ ] Tenant interno vê o menu completo, idêntico ao de hoje
- [ ] `temModulo()` funciona em qualquer componente
- [ ] `npm run build` sem erro

## Teste esperado

- Comando: `npm run build`
- Verificação manual: bloquear `contratos` para o tenant em local e conferir o menu; digitar a URL e conferir a página de indisponível
