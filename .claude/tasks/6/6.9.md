# Task 6.9 - Testes de bloqueio de módulo e de limites

## Objetivo

Garantir por teste que módulo bloqueado é inacessível por URL direta e que estourar limite não perde dado.

## Tipo

teste

## Arquivos a criar/modificar

- `tests/Feature/ModuloBloqueadoTest.php` -> criar
- `tests/Feature/LimitesDoPlanoTest.php` -> criar

## Contexto necessário (ler antes)

- `app/Services/ModuleService.php` -> precedência das regras
- `app/Http/Middleware/EnsureModuleIsActive.php` -> comportamento a testar
- `app/Services/LimitesDoPlanoService.php` -> estados de limite
- `tests/Feature/VazamentoEntreEmpresasTest.php` -> padrão de montagem de tenants (Plano 4)

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

`ModuloBloqueadoTest`:

1. Tenant sem o módulo financeiro recebe a página de indisponível em **cada** rota financeira, percorrendo a coleção de rotas com o middleware `module:financeiro`, não uma lista escrita à mão.
2. O mesmo tenant recebe 403 com JSON em rota financeira que devolve JSON.
3. Tenant com o módulo acessa normalmente.
4. Usuário com a permissão `financeiro-ver` em tenant sem o módulo continua barrado (as duas verificações são independentes).
5. Módulo `sempre_ativo` fica acessível em tenant sem plano algum.
6. Bloqueio pontual vence o plano que libera.
7. Liberação pontual com `liberado_ate` de ontem não libera; de hoje, libera.
8. Rebaixar plano de um tenant com dado no módulo bloqueado **não** apaga registro algum: contar antes e depois.
9. Reativar o módulo devolve o acesso e o dado continua lá.

`LimitesDoPlanoTest`:

1. `situacao()` devolve `ok`, `proximo` (a partir de 80%) e `estourado` corretamente.
2. Limite nulo é ilimitado, sem aviso.
3. Criar cliente acima do teto funciona e gera aviso.
4. Criar usuário acima do teto é recusado com mensagem.
5. Tenant interno não recebe aviso algum.
6. "OS do mês" conta pelo mês no fuso do negócio (testar com data de virada, 23h50 do último dia do mês em Brasília).

### Regras de negócio aplicáveis

- O caso 1 é o entregável explícito do plano ("acesso negado por URL direta") e usa a coleção de rotas para não envelhecer.
- O caso 8 é o que prova "rebaixar não apaga dado". Ele não pode ser afrouxado.
- Nenhum caso marcado como `skipped` ou `incomplete`.

### Critérios de aceitação

- [ ] `php artisan test --filter=ModuloBloqueadoTest` passa com os 9 casos
- [ ] `php artisan test --filter=LimitesDoPlanoTest` passa com os 6 casos
- [ ] `php artisan test` inteiro continua verde
- [ ] Remover o middleware de uma rota financeira faz o caso 1 falhar

## Teste esperado

- Comando: `php artisan test --filter=ModuloBloqueadoTest && php artisan test --filter=LimitesDoPlanoTest`

## Estimativa

alta - ~280 linhas | 2 arquivos
