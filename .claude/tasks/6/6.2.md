# Task 6.2 - Catálogo dos módulos controláveis

## Objetivo

Declarar o catálogo dos módulos em uma fonte única e semeá-lo no banco, vinculando tudo ao plano interno do tenant 1.

## Tipo

backend-estrutura

## Arquivos a criar/modificar

- `app/Support/CatalogoDeModulos.php` -> criar
- `database/seeders/ModulesSeeder.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/Module.php` -> criado na Task 6.1
- `app/Console/Commands/SyncPermissions.php` -> comando do Plano 2 com catálogo em método estático, mesmo padrão
- `.claude/prd/saas-multitenant.md` -> lista dos módulos controláveis

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

1. `App\Support\CatalogoDeModulos` com `catalogo(): array`, fonte única lida pelo seeder, pelo middleware e pelos testes:

   | chave | nome | sempre ativo |
   |---|---|---|
   | `clientes` | Clientes e endereços | sim |
   | `ordens_servico` | Ordens de serviço | sim |
   | `certificados` | Certificados | sim |
   | `financeiro` | Financeiro | não |
   | `estoque` | Estoque | não |
   | `contratos` | Contratos | não |
   | `portal_cliente` | Portal do cliente | não |
   | `app_tecnico` | App do técnico | não |
   | `notificacoes` | Notificações | não |
   | `roteirizacao` | Roteirização | não |
   | `nfse` | Nota fiscal de serviço | não |
   | `laudo_ia` | Laudo por IA | não |
   | `monitoramento` | Relatórios de monitoramento | não |

2. `ModulesSeeder`: `updateOrCreate` por chave (idempotente), avisa sobre módulo no banco que não está no catálogo sem apagar, e vincula **todos** os módulos ao plano do tenant interno.

3. Se ainda não houver plano interno, o seeder o cria: nome "Interno", valor zero, todos os limites nulos, e vincula ao tenant 1.

### Regras de negócio aplicáveis

- Módulo novo entra primeiro no catálogo. Criar `Module` direto no banco sem passar pelo catálogo quebra a rastreabilidade que o Plano 2 já estabeleceu para permissões.
- Os três módulos `sempre_ativo` são o produto mínimo. Bloqueá-los entregaria um sistema que não faz nada, o que não é plano comercial, é defeito.
- O tenant 1 recebe tudo liberado, sem cobrança. Essa é a garantia de que o cliente atual não percebe a chegada dos planos.
- Seeder idempotente: rodar de novo não duplica nem apaga.

### Critérios de aceitação

- [ ] `php artisan db:seed --class=ModulesSeeder` cria os 13 módulos
- [ ] Rodar duas vezes não duplica
- [ ] O plano interno existe e tem os 13 módulos vinculados
- [ ] O tenant 1 está no plano interno
- [ ] Módulo fora do catálogo é reportado, não apagado
- [ ] `CatalogoDeModulos::catalogo()` é a única lista no código

## Teste esperado

- Comando: `php artisan db:seed --class=ModulesSeeder && php artisan db:seed --class=ModulesSeeder`
- Verificação manual: `select chave, sempre_ativo from modules order by ordem`
