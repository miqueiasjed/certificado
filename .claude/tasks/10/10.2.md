# Task 10.2 - Conflito de horário e carga por técnico

## Objetivo

Detectar sobreposição de horário do mesmo técnico e apurar a carga de trabalho de cada um no período.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Services/DisponibilidadeService.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/WorkOrder.php` -> `scheduled_date`, `start_time`, `end_time`, `technician_id`
- `app/Models/Technician.php` -> dados do técnico
- `app/Support/BusinessDate.php` -> comparação de horário no fuso do negócio
- `app/Services/AgendaService.php` -> criado na Task 10.1

## Especificação

### O que fazer

`DisponibilidadeService`:

1. `conflitos(int $technicianId, string $data, ?string $inicio, ?string $fim, ?int $ignorarOsId = null): array` -> OS do mesmo técnico, na mesma data, com sobreposição de horário. `$ignorarOsId` exclui a própria OS ao editar.

2. Regra de sobreposição: dois intervalos colidem quando `inicioA < fimB` e `inicioB < fimA`. Intervalo encostado (uma termina 10:00, outra começa 10:00) **não** é conflito.

3. OS sem horário definido: mesma data e mesmo técnico gera **aviso**, não bloqueio. Sem hora não há como afirmar sobreposição, e travar por isso impediria o uso normal de quem não preenche horário.

4. `cargaPorTecnico(string $inicio, string $fim): array` -> por técnico: total de OS, total de horas agendadas, OS por dia, e a distribuição no período. Inclui a linha "sem técnico".

5. `tecnicosDisponiveis(string $data, ?string $inicio, ?string $fim): array` -> técnicos ativos sem conflito no horário, para a atribuição pelo calendário.

### Regras de negócio aplicáveis

- Conflito de horário do mesmo técnico é **bloqueado**, com aviso claro dizendo qual OS colide. Essa é a regra explícita do plano.
- Só há conflito quando as duas OS têm horário. Sem horário, é aviso.
- OS cancelada não gera conflito.
- Horas comparadas no fuso do negócio. `start_time` é `datetime` no model: comparar instante UTC produziria conflito fantasma na virada do dia.
- Carga considera apenas OS não canceladas.

### Critérios de aceitação

- [ ] Dois intervalos sobrepostos do mesmo técnico são detectados
- [ ] Intervalos encostados (10:00 fim / 10:00 início) não são conflito
- [ ] OS sem horário na mesma data gera aviso, não conflito
- [ ] `$ignorarOsId` impede a OS de conflitar consigo mesma
- [ ] OS cancelada não gera conflito
- [ ] Técnico de outra empresa nunca aparece na disponibilidade
- [ ] `cargaPorTecnico()` inclui a linha "sem técnico"
