# Task 3.4 - Registro de acesso: login, falha de login e logout

## Objetivo

Gravar em `access_logs` todo login bem-sucedido, toda tentativa recusada e todo logout, com IP e agente.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Listeners/RegistraAcesso.php` -> criar
- `app/Providers/AppServiceProvider.php` -> modificar (registro dos listeners)
- `app/Http/Controllers/AuthController.php` -> modificar apenas se o login não disparar os eventos padrão

## Contexto necessário (ler antes)

- `app/Http/Controllers/AuthController.php` -> como o login é feito hoje; confirmar se usa `Auth::attempt()` (dispara `Login`/`Failed`) ou verificação manual
- `app/Models/AccessLog.php` -> estrutura criada na Task 3.1
- `app/Listeners/RegistraExecucaoAgendada.php` -> listener existente, referência de estilo

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

1. Criar `app/Listeners/RegistraAcesso.php` com métodos:
   - `aoEntrar(\Illuminate\Auth\Events\Login $evento)` -> grava `evento = login`, `user_id`, `email`
   - `aoFalhar(\Illuminate\Auth\Events\Failed $evento)` -> grava `evento = login_falhou`, `email` das credenciais, `user_id` nulo. **Nunca** gravar a senha tentada, nem em `detalhes`
   - `aoSair(\Illuminate\Auth\Events\Logout $evento)` -> grava `evento = logout`

2. Registrar os três no `AppServiceProvider::boot()` com `Event::listen(...)`.

3. Se `AuthController` não usar `Auth::attempt()`, os eventos nativos não disparam. Nesse caso, disparar os eventos manualmente (`event(new Failed('web', null, $credenciais))`) em vez de chamar o listener direto: mantém um único ponto de captura.

4. Todo `AccessLog` recebe `ip` de `request()->ip()` e `user_agent` de `request()->userAgent()`, truncado em 255 caracteres.

### Regras de negócio aplicáveis

- Senha nunca é gravada, em nenhuma forma, nem com hash.
- Falha de login grava o e-mail digitado mesmo quando o usuário não existe: é justamente esse o padrão que revela tentativa de invasão.
- Falha ao gravar o log não pode impedir o login nem a resposta de erro: envolver em `try/catch` com `Log::error()`.
- O evento `tenant_assumido` já está previsto no enum da tabela e será usado pelo Plano 5. Não implementar aqui.

### Critérios de aceitação

- [ ] Login válido grava um registro com `evento = login` e `user_id` preenchido
- [ ] Senha errada grava `evento = login_falhou` com o e-mail digitado e `user_id` nulo
- [ ] E-mail inexistente também grava `login_falhou`
- [ ] Logout grava `evento = logout`
- [ ] Nenhum registro contém a senha em qualquer campo
- [ ] IP e user agent preenchidos nos três casos

## Teste esperado

- Verificação manual: errar a senha uma vez, acertar depois, sair, e conferir `select evento, email, user_id from access_logs order by id desc limit 3`
