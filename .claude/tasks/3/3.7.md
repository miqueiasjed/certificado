# Task 3.7 - Histórico embutido nas telas dos registros sensíveis

## Objetivo

Colocar o bloco de histórico nas telas de detalhe de ordem de serviço, certificado, contrato e lançamento financeiro.

## Tipo

frontend-pagina

## Arquivos a criar/modificar

- `resources/js/Pages/WorkOrders/Show.vue` (ou equivalente de detalhe) -> modificar
- `resources/js/Pages/Certificates/Show.vue` -> modificar
- `resources/js/Pages/Contracts/Show.vue` -> modificar
- `resources/js/Pages/FinancialEntries/Show.vue` (ou a tela de detalhe existente) -> modificar

## Contexto necessário (ler antes)

- `resources/js/Components/HistoricoRegistro.vue` -> componente criado na Task 3.6
- `resources/js/Pages/WorkOrders/` -> conferir o nome real do arquivo de detalhe antes de editar

## Skills necessárias

- `frontend-design-system`

## Especificação

### O que fazer

1. Antes de editar, listar os arquivos de cada pasta e identificar a tela de detalhe real de cada módulo. Se algum módulo não tiver tela de detalhe (só edição), embutir na tela de edição, ao final do formulário.
2. Em cada uma, importar `HistoricoRegistro` e renderizar ao final do conteúdo principal, passando `tipo` e `id` conforme o mapa de apelidos da Task 3.5:
   - OS -> `tipo="ordem-servico"`
   - Certificado -> `tipo="certificado"`
   - Contrato -> `tipo="contrato"`
   - Lançamento financeiro -> `tipo="lancamento-financeiro"`
3. O bloco fica sempre por último, depois das abas e das ações. Ele é consulta, não fluxo de trabalho.

### Regras de negócio aplicáveis

- Nenhuma outra alteração nessas telas. Task de integração, não de redesenho.
- Se a tela de OS usa abas (`WorkOrderTabs.vue`), o histórico fica **fora** das abas, ao final da página, para não competir com o fluxo de execução.
- Apelido de tipo diferente do mapa da Task 3.5 gera 404: conferir a grafia exata.

### Critérios de aceitação

- [ ] As quatro telas exibem o bloco de histórico ao final
- [ ] Abrir o histórico em cada uma traz os registros do próprio recurso
- [ ] Nenhuma requisição de auditoria dispara ao abrir a tela, só ao clicar
- [ ] `npm run build` sem erro
- [ ] Layout mobile intacto nas quatro telas

## Teste esperado

- Comando: `npm run build`
- Verificação manual: abrir uma OS, um certificado, um contrato e um lançamento e expandir o histórico em cada

baixa - ~40 linhas | 4 arquivos
