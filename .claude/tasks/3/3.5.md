# Task 3.5 - Service e endpoint de consulta do histórico

## Objetivo

Entregar o histórico de alterações de um registro em JSON, já formatado para exibição, protegido por permissão.

## Tipo

backend-endpoint

## Arquivos a criar/modificar

- `app/Services/AuditoriaService.php` -> criar
- `app/Http/Controllers/AuditLogController.php` -> criar
- `routes/web.php` -> modificar

## Contexto necessário (ler antes)

- `app/Models/AuditLog.php` -> estrutura do registro
- `app/Http/Controllers/WorkOrderPhotoController.php` -> controller enxuto que devolve JSON, referência de estilo
- `routes/web.php` -> agrupamento de rotas e middleware de permissão do Plano 2
- `.claude/skills/permissoes-e-multitenancy/SKILL.md` -> como declarar permissão em rota

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`
- `datas-timezone`

## Especificação

### O que fazer

1. Acrescentar `auditoria-ver` e `acesso-log-ver` ao catálogo do comando `permissions:sync` (Task 2.2), no módulo `administracao`, e concedê-las apenas ao papel `administrador` no seeder de papéis (Task 2.3).

2. `AuditoriaService` com:
   - `historicoDe(string $tipo, int $id, int $porPagina = 20): LengthAwarePaginator` -> registros de `audit_logs` do model informado, mais recentes primeiro, com o usuário carregado
   - `descreverAlteracao(AuditLog $log): array` -> converte `valores_antes`/`valores_depois` em uma lista de `['campo' => ..., 'rotulo' => ..., 'antes' => ..., 'depois' => ...]`, com rótulos em português e valores formatados (data pelo utilitário do projeto, decimal com 2 casas, booleano como Sim/Não)
   - `$tipo` recebido é validado contra uma **lista fechada** de models auditados. Nome de classe vindo da requisição nunca é instanciado direto

3. `AuditLogController@index` -> `GET /audit-logs/{tipo}/{id}`, devolve JSON com os registros já descritos. Controller fino: só chama o Service.

4. Registrar a rota dentro do grupo autenticado, com `->middleware('permission:auditoria-ver')`.

### Regras de negócio aplicáveis

- `$tipo` vem da URL. Mapear apelido para classe por array fixo (`ordem-servico` => `WorkOrder::class`, `certificado` => `Certificate::class`, ...). Aceitar FQCN da requisição abriria enumeração de qualquer model.
- Data formatada no fuso do negócio, usando os utilitários do projeto. Nunca devolver ISO cru esperando que o frontend converta.
- Campo sem rótulo mapeado é exibido com o nome da coluna, e não escondido: histórico incompleto vale menos que histórico feio.
- Sem `company_id` nesta task; o escopo por empresa chega no Plano 4.

### Critérios de aceitação

- [ ] `GET /audit-logs/ordem-servico/1` devolve os registros daquela OS
- [ ] Usuário sem `auditoria-ver` recebe 403
- [ ] Tipo desconhecido devolve 404, não erro 500
- [ ] Datas vêm formatadas em pt-BR no fuso do negócio
- [ ] Alteração de valor decimal aparece como `1.500,00`, não `1500.0000`
- [ ] Controller não contém regra alguma além de delegar ao Service
