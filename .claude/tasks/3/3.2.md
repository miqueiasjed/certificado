# Task 3.2 - Trait Auditavel com captura de valores antes e depois

## Objetivo

Criar a trait que, aplicada a um model, grava automaticamente em `audit_logs` toda criação, alteração e exclusão, com os valores antes e depois.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Models/Concerns/Auditavel.php` -> criar
- `config/auditoria.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/AuditLog.php` -> estrutura criada na Task 3.1
- `app/Support/BusinessDate.php` -> utilitário de data e fuso do projeto
- `.claude/skills/laravel-arquitetura/SKILL.md` -> convenções

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

1. Criar `config/auditoria.php`:
   ```php
   return [
       // Campos nunca gravados no log, em nenhum model
       'campos_ignorados' => ['password', 'remember_token', 'updated_at', 'created_at'],
       // Dias de retenção do histórico antes do expurgo (Task 3.8)
       'dias_de_retencao' => env('AUDITORIA_DIAS_DE_RETENCAO', 730),
   ];
   ```

2. Criar a trait `App\Models\Concerns\Auditavel` com `bootAuditavel()` registrando:
   - `created` -> grava `acao = criado`, `valores_antes = null`, `valores_depois` com os atributos auditáveis
   - `updated` -> grava `acao = alterado` somente se houver campo auditável realmente alterado (`getChanges()` filtrado). Sem mudança relevante, não grava nada
   - `deleted` -> grava `acao = excluido`, `valores_antes` com os atributos, `valores_depois = null`

3. Métodos da trait:
   - `atributosAuditaveis(): array` -> campos ignorados vêm de `config('auditoria.campos_ignorados')` mais a propriedade opcional `$naoAuditar` declarada no model
   - `auditLogs()` -> `morphMany(AuditLog::class, 'auditable')`, ordenado por `created_at desc`
   - método privado que monta o registro: `user_id` de `auth()->id()`, `autor_nome` de `auth()->user()?->name` (ou `'Sistema'` quando não há usuário, caso de comando artisan e fila), `ip` e `user_agent` de `request()` quando existir requisição

4. A gravação usa `AuditLog::create()`. Falha ao gravar auditoria **não** pode derrubar a operação de negócio: envolver em `try/catch` e registrar em `Log::error()`.

### Regras de negócio aplicáveis

- Campo de senha nunca entra no log, nem em `valores_antes`.
- Update sem alteração efetiva não gera registro. Salvar um formulário sem mudar nada não polui o histórico.
- Fora de requisição HTTP (comando, seeder, fila) o autor é `Sistema` e `ip` fica nulo. Nunca lançar exceção por ausência de usuário autenticado.
- A trait não decide *quais* models são auditados. Isso é a Task 3.3.

### Critérios de aceitação

- [ ] Model com a trait gera um `AuditLog` com `acao = criado` ao ser criado
- [ ] Alterar um campo auditável gera registro com `valores_antes` e `valores_depois` contendo apenas os campos que mudaram
- [ ] `save()` sem alteração não gera registro
- [ ] Excluir gera registro com `acao = excluido` e `valores_antes` preenchido
- [ ] Campo `password` não aparece em nenhum log
- [ ] Criar em `php artisan tinker` (sem usuário autenticado) grava `autor_nome = 'Sistema'` sem erro
