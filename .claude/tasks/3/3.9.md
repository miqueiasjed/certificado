# Task 3.9 - Testes de auditoria e de registro de acesso

## Objetivo

Garantir por teste que a alteração é registrada, que o registro não pode ser apagado pela aplicação e que login e falha de login ficam gravados.

## Tipo

teste

## Arquivos a criar/modificar

- `tests/Feature/AuditoriaTest.php` -> criar
- `tests/Feature/RegistroDeAcessoTest.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/Concerns/Auditavel.php` -> comportamento a testar
- `app/Models/AuditLog.php` -> proteção contra exclusão
- `tests/Feature/` -> testes existentes, para seguir o padrão de setup do projeto
- `app/Services/AuditoriaService.php` -> lista fechada de tipos

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

`AuditoriaTest`:

1. Criar uma OS autenticado gera `AuditLog` com `acao = criado`, `user_id` do autor e `autor_nome` preenchido.
2. Alterar um campo gera `acao = alterado`, com `valores_antes` e `valores_depois` contendo **apenas** o campo alterado.
3. Salvar sem alterar nada não gera registro novo.
4. Excluir gera `acao = excluido`.
5. `AuditLog::first()->delete()` lança exceção e o registro continua no banco.
6. `AuditLog::first()->update(['acao' => 'x'])` lança exceção.
7. Alterar a senha de um usuário não grava `password` em nenhum campo do log.
8. `GET /audit-logs/ordem-servico/{id}` sem a permissão `auditoria-ver` devolve 403; com a permissão, devolve os registros.
9. `GET /audit-logs/tipo-inventado/1` devolve 404.
10. `auditoria:purge --dias=0` remove os registros antigos e mantém a tabela funcional.

`RegistroDeAcessoTest`:

1. Login válido grava `evento = login` com `user_id`.
2. Senha errada grava `login_falhou` com o e-mail digitado e `user_id` nulo.
3. E-mail inexistente também grava `login_falhou`.
4. Logout grava `evento = logout`.
5. Nenhum `access_logs.detalhes` contém a senha enviada.

### Regras de negócio aplicáveis

- Testes usam `RefreshDatabase` e fábricas quando existirem; onde não houver factory, criar o registro direto no teste, sem criar factory nova fora de escopo.
- O teste 5 do `AuditoriaTest` é o que fecha o entregável "não pode ser apagada" do plano. Ele não pode ser afrouxado.

### Critérios de aceitação

- [ ] `php artisan test --filter=AuditoriaTest` passa com os 10 casos
- [ ] `php artisan test --filter=RegistroDeAcessoTest` passa com os 5 casos
- [ ] `php artisan test` inteiro continua verde
- [ ] Nenhum teste depende de dado pré-existente no banco

## Teste esperado

- Comando: `php artisan test --filter=AuditoriaTest && php artisan test --filter=RegistroDeAcessoTest`

média - ~220 linhas | 2 arquivos
