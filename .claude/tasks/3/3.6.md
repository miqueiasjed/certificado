# Task 3.6 - Componente de linha do tempo do histórico

## Objetivo

Criar o componente Vue que busca e exibe o histórico de alterações de um registro em linha do tempo, pronto para ser embutido em qualquer tela.

## Tipo

frontend-componente

## Arquivos a criar/modificar

- `resources/js/Components/HistoricoRegistro.vue` -> criar

## Contexto necessário (ler antes)

- `resources/js/utils/formatDate.js` -> utilitários de data do frontend

## Especificação

### O que fazer

Componente `HistoricoRegistro.vue`, `<script setup>` em JavaScript puro:

**Props:** `tipo` (string, obrigatória), `id` (number, obrigatória), `titulo` (string, padrão `'Histórico de alterações'`).

**Comportamento:**

1. Busca sob demanda: o bloco começa recolhido, com o título e um botão "Ver histórico". A requisição a `/audit-logs/{tipo}/{id}` só sai no primeiro clique. Carregar em toda abertura de OS custa uma consulta que quase ninguém abre.
2. Estados tratados: carregando (esqueleto ou spinner), vazio ("Nenhuma alteração registrada"), erro (mensagem com botão de tentar de novo), carregado.
3. Cada item da linha do tempo mostra: ícone por ação (criado, alterado, excluído), autor, data e hora formatadas, e a lista de campos alterados no formato `Rótulo: antes -> depois`. Valor antigo em cinza riscado, novo em destaque.
4. Paginação simples: botão "Carregar mais" quando houver próxima página.
5. Se o usuário não tiver a permissão `auditoria-ver`, o componente não renderiza nada (checar `auth.user.permissoes` compartilhado pelo Plano 2).

### Regras de negócio aplicáveis

- Nada de `toLocaleDateString`. Usar os utilitários de data do projeto.
- O componente não interpreta payload cru: os rótulos e a formatação já vêm prontos do backend (Task 3.5). Ele só desenha.
- Esconder o bloco por permissão é conforto visual, não segurança. A rota já está protegida no backend.
- Sem emoji nos ícones; usar SVG inline no padrão do projeto.

### Critérios de aceitação

- [ ] O componente não dispara requisição antes do primeiro clique
- [ ] Estados de carregando, vazio e erro estão implementados e visíveis
- [ ] Data e hora aparecem no fuso do negócio, sem `toLocaleDateString`
- [ ] Usuário sem `auditoria-ver` não vê o bloco
- [ ] Funciona em tela de celular sem quebrar o layout
- [ ] `npm run build` sem erro nem aviso novo

## Teste esperado

- Comando: `npm run build`
- Verificação manual: embutir temporariamente em uma tela de OS e abrir o histórico de uma OS já editada
