# Task 7.4 - Service de assinatura do tenant

## Objetivo

Concentrar a criação, a troca de plano, o cancelamento e a mudança de forma de pagamento da assinatura, com o tenant interno imune a tudo isso.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Services/SubscriptionService.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/Subscription.php` -> estrutura criada na Task 7.1
- `app/Contracts/GatewayAssinatura.php` -> contrato injetado
- `app/Services/TenantService.php` -> criado na Task 5.4, referência de estilo e regra do tenant interno

## Especificação

### O que fazer

`SubscriptionService`, com `GatewayAssinatura` injetado no construtor:

1. `assinar(Company $empresa, Plan $plano, string $formaPagamento): Subscription` -> cria no gateway, grava a assinatura, define `proxima_cobranca_em`. Recusa se a empresa for `is_internal`.
2. `trocarPlano(Subscription $assinatura, Plan $novoPlano): Subscription` -> troca no gateway e no banco. Rebaixamento passa a valer no próximo ciclo, e o efeito nos módulos é do Plano 6, aplicado sozinho pelo vínculo do plano.
3. `trocarFormaDePagamento(Subscription $assinatura, string $forma): Subscription`.
4. `cancelar(Subscription $assinatura, string $motivo): Subscription` -> cancela no gateway, grava motivo e instante, e mantém o acesso até o fim do período já pago.
5. `situacaoDe(Company $empresa): array` -> plano, situação, próxima cobrança, forma de pagamento, e se está imune (interno).

Toda operação que chama o gateway grava o resultado em transação com o banco: falha no gateway não deixa assinatura ativa no banco, e falha no banco depois de criar no gateway registra pendência em log com o id do gateway, para conciliação manual.

### Regras de negócio aplicáveis

- **Tenant com `is_internal = true` não tem assinatura, não é cobrado e não pode ser bloqueado.** Toda entrada deste Service verifica isso primeiro. Um erro aqui custa a receita atual do negócio.
- Cancelar não apaga dado nem corta acesso na hora: o tenant usa até o fim do período pago.
- Rebaixar plano nunca apaga dado (regra do Plano 6, reafirmada aqui porque a troca de plano passa por este Service).
- Datas de cobrança calculadas por dia no fuso do negócio.

### Critérios de aceitação

- [ ] `assinar()` no tenant interno lança exceção e não cria nada, nem no gateway
- [ ] `assinar()` em tenant comum cria no gateway e no banco, em transação
- [ ] Falha do gateway não deixa assinatura no banco
- [ ] Falha do banco após sucesso no gateway registra pendência em log com o id do gateway
- [ ] `cancelar()` mantém o acesso até o fim do período pago
- [ ] `trocarPlano()` não apaga registro de domínio algum
- [ ] `situacaoDe()` no tenant interno devolve imune
