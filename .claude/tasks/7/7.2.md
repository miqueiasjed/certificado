# Task 7.2 - Interface GatewayAssinatura e objetos de transporte

## Objetivo

Definir o contrato do gateway de assinatura, com objetos de transporte próprios, para que trocar de provedor não toque no domínio.

## Tipo

backend-estrutura

## Arquivos a criar/modificar

- `app/Contracts/GatewayAssinatura.php` -> criar
- `app/Support/Gateway/DadosDeAssinatura.php` -> criar (mais os demais DTOs no mesmo diretório)

## Contexto necessário (ler antes)

- `app/Models/Subscription.php` e `app/Models/Invoice.php` -> criados na Task 7.1
- `.claude/prd/saas-multitenant.md` -> seção de assinaturas
- `app/Services/` -> padrão de organização do projeto

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

1. Interface `App\Contracts\GatewayAssinatura`:
   - `criarAssinatura(Company $empresa, Plan $plano, string $formaPagamento): RespostaDeAssinatura`
   - `cancelarAssinatura(string $idNoGateway): void`
   - `trocarPlano(string $idNoGateway, Plan $novoPlano): RespostaDeAssinatura`
   - `gerarCobranca(Invoice $fatura): RespostaDeCobranca` -> devolve link, linha digitável ou QR conforme a forma
   - `consultarCobranca(string $idNoGateway): RespostaDeCobranca`
   - `validarWebhook(Request $requisicao): bool` -> assinatura ou token do provedor
   - `interpretarWebhook(array $payload): EventoDeGateway` -> traduz o payload do provedor para o vocabulário do domínio

2. Objetos de transporte simples (classes `readonly`), em `app/Support/Gateway/`: `RespostaDeAssinatura`, `RespostaDeCobranca`, `EventoDeGateway` (com `eventoId`, `tipo` normalizado, `faturaIdNoGateway`, `situacao`, `pagoEm`).

3. Tipos normalizados de evento, como constantes: `cobranca_paga`, `cobranca_vencida`, `cobranca_cancelada`, `assinatura_cancelada`, `desconhecido`.

4. Registrar o binding no `AppServiceProvider`, resolvendo a implementação por `config('services.gateway_assinatura')`.

### Regras de negócio aplicáveis

- Nenhum tipo do PagBank atravessa esta interface. Array cru do provedor circulando pelo domínio é o que impede a troca de gateway.
- Evento de tipo desconhecido é traduzido como `desconhecido` e mesmo assim registrado. Ignorar o que não se entende é como se perde confirmação de pagamento.
- Esta task não implementa nada: só o contrato e os objetos. A implementação é a Task 7.3.
- Sem chamada HTTP, sem credencial, sem teste de integração aqui.

### Critérios de aceitação

- [ ] A interface declara os 7 métodos com tipos explícitos
- [ ] Nenhum método recebe ou devolve array associativo solto
- [ ] Os objetos de transporte são `readonly` e imutáveis
- [ ] O binding resolve pela configuração
- [ ] `php artisan test` continua passando
- [ ] Nenhuma referência a PagBank fora da configuração
