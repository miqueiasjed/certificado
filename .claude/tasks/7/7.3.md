# Task 7.3 - Implementação PagBank do gateway

## Objetivo

Implementar o contrato de gateway contra a API do PagBank, com credencial em configuração e registro de toda chamada.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Services/Gateway/PagBankGateway.php` -> criar
- `config/services.php` -> modificar
- `.env.example` -> modificar

## Contexto necessário (ler antes)

- `app/Contracts/GatewayAssinatura.php` -> contrato criado na Task 7.2
- `app/Support/Gateway/` -> objetos de transporte
- Documentação da API de assinaturas do PagBank -> endpoints, autenticação e formato de webhook
- `config/services.php` -> padrão de configuração do projeto

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

1. `PagBankGateway implements GatewayAssinatura`, usando o cliente HTTP do Laravel:
   - Base URL e token vindos de `config('services.pagbank')`, com URL de sandbox e de produção separadas
   - `timeout` explícito e `retry` para erro de rede, **nunca** para erro 4xx
   - Toda chamada registrada em log com o endpoint, o status e o tempo, **sem** o token e sem dado de cartão
   - Erro do provedor traduzido em exceção de domínio própria (`GatewayIndisponivelException`, `GatewayRecusouException`), com a mensagem do provedor preservada

2. `validarWebhook()` conforme o mecanismo do PagBank (token de autenticidade no cabeçalho). Sem validação, qualquer um confirma pagamento por POST.

3. `interpretarWebhook()` traduz o payload para `EventoDeGateway`, mapeando os tipos do provedor para as constantes normalizadas.

4. Configuração em `config/services.php` e chaves no `.env.example`: `PAGBANK_TOKEN`, `PAGBANK_BASE_URL`, `PAGBANK_WEBHOOK_TOKEN`, `PAGBANK_SANDBOX`.

5. Dado de cartão **não** trafega pelo servidor: usar a tokenização do provedor no frontend e receber apenas o token. Se a API exigir outro fluxo, reportar antes de implementar qualquer caminho que faça o cartão passar pela aplicação.

### Regras de negócio aplicáveis

- Token e credencial nunca em log, nunca em mensagem de erro exibida, nunca em `GatewayEvent.payload` de saída.
- Retry só em falha de rede e 5xx. Reenviar uma cobrança recusada gera cobrança duplicada.
- Ambiente de sandbox é o padrão em desenvolvimento. Subir com sandbox em produção é erro de configuração, e o comando de diagnóstico precisa deixar isso visível.
- Nenhuma regra de negócio aqui: esta classe traduz protocolo, quem decide é o Service da Task 7.4.

### Critérios de aceitação

- [ ] A classe implementa todos os métodos da interface
- [ ] Credencial vem só de configuração, nunca escrita no código
- [ ] Nenhum log contém token ou dado de cartão
- [ ] Erro 4xx não é repetido; erro de rede é
- [ ] `validarWebhook()` recusa requisição sem o token correto
- [ ] `interpretarWebhook()` devolve `desconhecido` para tipo não mapeado, sem lançar exceção
- [ ] Testes com HTTP falso (`Http::fake()`) cobrem sucesso, recusa e indisponibilidade
