# Task 7.11 - Testes de assinatura, webhook e imunidade do tenant interno

## Objetivo

Garantir por teste que o tenant interno é imune a cobrança e a bloqueio, que o webhook é idempotente e que a régua de inadimplência não perde dado.

## Tipo

teste

## Arquivos a criar/modificar

- `tests/Feature/TenantInternoImuneTest.php` -> criar
- `tests/Feature/GatewayWebhookTest.php` -> criar
- `tests/Feature/InadimplenciaTest.php` -> criar

## Contexto necessário (ler antes)

- `app/Services/SubscriptionService.php`, `InvoiceService.php`, `InadimplenciaService.php` -> regras a testar
- `app/Http/Controllers/GatewayWebhookController.php` -> idempotência
- `app/Contracts/GatewayAssinatura.php` -> contrato a substituir por dublê nos testes
- `tests/Feature/VazamentoEntreEmpresasTest.php` -> padrão de montagem de tenants

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`
- `datas-timezone`

## Especificação

### O que fazer

Substituir `GatewayAssinatura` por um dublê registrado no container. Nenhum teste chama a API do PagBank.

`TenantInternoImuneTest` (o mais importante do plano):

1. `SubscriptionService::assinar()` no tenant interno lança exceção e não cria nada.
2. `plataforma:gerar-faturas` não gera fatura para o tenant interno, mesmo com plano vinculado.
3. `InadimplenciaService::avaliar()` não toca no tenant interno, mesmo com fatura fictícia vencida há 90 dias.
4. `TenantService::suspender()` no tenant interno lança exceção.
5. O tenant interno nunca fica com `situacao = 'suspensa'` por nenhum caminho automático.
6. O tenant interno não aparece nos números do painel de receita.
7. O usuário do tenant interno acessa o sistema normalmente com uma fatura fictícia vencida no banco.

`GatewayWebhookTest`:

1. Token inválido devolve 401 e não grava `GatewayEvent`.
2. Evento válido grava e processa, e a fatura vira paga.
3. O mesmo `evento_id` enviado duas vezes gera um único `GatewayEvent` e um único efeito (fatura não é marcada como paga duas vezes, próxima cobrança não avança duas vezes).
4. Evento de tipo desconhecido é gravado, marcado como processado, sem erro e sem efeito.
5. Erro no processamento devolve 200, grava `erro` e incrementa `tentativas`.
6. `plataforma:reprocessar-eventos` reprocessa evento com erro e o marca como processado.
7. A rota funciona sem autenticação e sem token CSRF.

`InadimplenciaTest`:

1. Vencida dentro da tolerância marca em atraso, sem suspender.
2. Vencida além da tolerância suspende a empresa.
3. Empresa suspensa é redirecionada ao acessar rota do sistema.
4. Empresa suspensa acessa `/assinatura` e logout normalmente.
5. Pagar reativa: `marcarComoPaga()` devolve o acesso na requisição seguinte.
6. Contagem de registros de domínio do tenant é idêntica antes da suspensão e depois da reativação.
7. Vencimento comparado por dia no fuso do negócio: fatura que vence hoje não suspende às 21h de Brasília.

### Regras de negócio aplicáveis

- `TenantInternoImuneTest` é o portão de subida deste plano. Sem ele verde, o código não vai para produção: um erro na régua derruba a operação do cliente atual, que é a receita atual do negócio.
- O caso 6 do `InadimplenciaTest` prova que bloqueio não perde dado.
- O caso 3 do `GatewayWebhookTest` prova a idempotência exigida pelo plano.
- Nenhum caso marcado como `skipped` ou `incomplete`.

### Critérios de aceitação

- [ ] `php artisan test --filter=TenantInternoImuneTest` passa com os 7 casos
- [ ] `php artisan test --filter=GatewayWebhookTest` passa com os 7 casos
- [ ] `php artisan test --filter=InadimplenciaTest` passa com os 7 casos
- [ ] `php artisan test` inteiro continua verde
- [ ] Nenhum teste faz chamada HTTP real
- [ ] Remover a verificação de `is_internal` de qualquer Service faz `TenantInternoImuneTest` falhar
