# Task 12.6 - PWA instalável com service worker e casca offline

## Objetivo

Tornar o aplicativo do técnico instalável na tela inicial do celular e capaz de abrir sem rede.

## Tipo

config

## Arquivos a criar/modificar

- `vite.config.js` -> modificar
- `public/manifest.webmanifest` -> criar
- `resources/js/app-tecnico.js` -> criar (ponto de entrada próprio)
- `resources/views/app-tecnico.blade.php` -> criar

## Contexto necessário (ler antes)

- `vite.config.js` -> configuração atual de build
- `resources/js/app.js` -> ponto de entrada do sistema web
- `resources/views/app.blade.php` -> layout Inertia atual
- `routes/web.php` -> onde a rota `/app` é registrada

## Skills necessárias

- `frontend-design-system`

## Especificação

### O que fazer

1. Instalar `vite-plugin-pwa` e configurar `registerType: 'prompt'`. Motivo de `prompt` em vez de `autoUpdate`: atualizar sozinho no meio de uma OS em execução descartaria o estado da tela. A nova versão é oferecida e o técnico decide quando aplicar.

2. `manifest.webmanifest`: nome, nome curto, `start_url: /app`, `display: standalone`, `orientation: portrait`, cor de tema no verde do sistema e ícones em 192 e 512, mais o `maskable`.

3. Estratégia de cache do service worker:
   - casca do aplicativo (HTML, JS, CSS): `precache`, atualizado na nova versão;
   - `/api/app/*`: **nunca cacheado pelo service worker**. Dado offline vive no IndexedDB da Task 12.7, com controle próprio de validade. Cache de resposta de API aqui criaria uma segunda fonte da verdade;
   - foto e logo: `cache-first` com teto de 50 itens.

4. Ponto de entrada separado (`app-tecnico.js`) e rota `/app` própria, fora do Inertia do sistema web: o aplicativo tem ciclo de vida offline e não deve carregar o bundle inteiro do painel.

5. Tela de "atualização disponível" discreta, com um botão de aplicar.

### Regras de negócio aplicáveis

- O aplicativo abre offline em qualquer situação. Abrir e mostrar erro de rede na primeira tela é falha de aceitação desta task.
- HTTPS é obrigatório para service worker e câmera. Deixar isso registrado no arquivo do plano de execução em produção.
- Nada de dado de negócio no cache do service worker. A separação entre casca (service worker) e dado (IndexedDB) é o que evita mostrar informação velha sem saber.
- Sem emoji nos textos do aplicativo.

### Critérios de aceitação

- [ ] O navegador oferece instalar o aplicativo na tela inicial
- [ ] Instalado, abre em tela cheia sem barra do navegador
- [ ] Abrir em modo avião mostra a interface, sem erro de rede
- [ ] Nenhuma resposta de `/api/app/*` aparece no cache do service worker
- [ ] Nova versão gera o aviso de atualização e só aplica ao ser confirmada
- [ ] `npm run build` gera o service worker e o manifesto

## Teste esperado

- Comando: `npm run build`
- Verificação manual: instalar em Android real, ativar o modo avião e abrir o aplicativo
