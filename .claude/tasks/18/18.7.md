# Task 18.7 - Endpoints financeiros e troca da leitura dos painéis

## Objetivo

Expor os títulos, o aging e a previsão, e passar os painéis existentes a ler do modelo novo sem mudar nenhum número.

## Tipo

backend-endpoint

## Arquivos a criar/modificar

- `app/Http/Controllers/ReceivableController.php` -> criar
- `app/Http/Controllers/PayableController.php` -> criar
- `app/Http/Controllers/FinancialDashboardController.php` -> modificar
- `routes/web.php` -> modificar

## Contexto necessário (ler antes)

- `app/Http/Controllers/FinancialDashboardController.php` -> o que os painéis mostram hoje
- `app/Services/Financial/AgingService.php` e `CashForecastService.php` -> Task 18.6
- `app/Services/Financial/ConferenciaDeTotais.php` -> Task 18.2, reaproveitado para conferir
- `.claude/tasks/2/2.6.md` -> as rotas financeiras já protegidas por permissão

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

1. CRUD e ações em `/contas-a-receber` e `/contas-a-pagar`: listar com filtros (situação, período, cliente ou fornecedor, categoria), criar, baixar, estornar e cancelar.

2. `/financeiro/inadimplencia` (aging), `/financeiro/previsao` (previsão de caixa) e `/contas` (plano de contas, CRUD).

3. Trocar a leitura dos painéis existentes para o modelo novo, **um painel por vez**, e cada troca conferida com `ConferenciaDeTotais::comparar()` antes de subir. Este é o ponto mais sensível do plano: é a tela que o cliente usa todo dia.

4. Todas as rotas sob as permissões financeiras do Plano 2, e sob o middleware do módulo `financeiro` do Plano 6.

5. Permissões novas: `financeiro.titulos`, `financeiro.estornar`, `financeiro.plano_de_contas`.

6. Manter o endpoint antigo funcionando até a troca de cada painel ser confirmada em produção. Remover código morto é task posterior, não parte desta.

### Regras de negócio aplicáveis

- Troca de leitura painel por painel, com conferência de totais em cada uma. Trocar tudo de uma vez impede saber qual painel quebrou quando um número não bater.
- O número que o cliente vê hoje não muda. Se mudar, a troca é revertida e a diferença é investigada antes de qualquer nova tentativa.
- Estorno em rota separada, com permissão própria: é a ação que altera caixa fechado.
- Nenhuma rota financeira fica sem permissão, seguindo o que o Plano 2 já estabeleceu.

### Critérios de aceitação

- [ ] Os CRUDs de receber e pagar funcionam com filtros
- [ ] Baixa e estorno funcionam pelos endpoints
- [ ] Aging e previsão respondem corretamente
- [ ] Cada painel trocado tem a conferência de totais registrada
- [ ] Nenhum total de painel mudou depois da troca
- [ ] Usuário sem permissão financeira recebe 403 em todas as rotas novas
- [ ] Tenant sem o módulo `financeiro` vê a página de indisponível

## Teste esperado
