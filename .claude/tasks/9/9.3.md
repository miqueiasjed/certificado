# Task 9.3 - Cálculo das datas de visita do contrato

## Objetivo

Calcular as datas previstas de visita de um contrato a partir do início, da periodicidade e da vigência.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Services/CalendarioDeVisitasService.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/Contract.php` -> `start_date`, `end_date`, `service_type`, periodicidade nova
- `app/Support/BusinessDate.php` -> toda data calculada no fuso do negócio
- `.claude/skills/datas-timezone/SKILL.md` -> regras de data do projeto

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

`CalendarioDeVisitasService`, sem acesso a escrita, só cálculo:

1. `datasPrevistas(Contract $contrato, ?string $ate = null): array` -> lista de `['numero' => n, 'data' => 'Y-m-d']` a partir de `start_date`, avançando pela periodicidade, até `end_date` ou até o limite informado, o que vier primeiro.

2. Regras de avanço:
   - unidade `dias` e `semanas` -> soma simples
   - unidade `meses` -> `addMonthsNoOverflow`. Contrato que começa em 31 de janeiro com visita mensal precisa cair em 28 de fevereiro, não em 3 de março
   - contrato `pontual` -> devolve array vazio
   - contrato sem periodicidade preenchida -> array vazio, sem exceção (é a pendência do backfill)

3. `proximasDatas(Contract $contrato, int $meses = 6): array` -> só as datas futuras dentro da janela.

4. `dataDaVisita(Contract $contrato, int $numero): ?string` -> data da enésima visita, para renumeração.

5. Nenhuma data cai fora da vigência: `start_date` é a primeira visita, e nada passa de `end_date`.

### Regras de negócio aplicáveis

- Toda data calculada por dia no fuso do negócio, nunca com `now()` cru nem instante UTC.
- `addMonthsNoOverflow` é obrigatório. O comportamento padrão de soma de mês em dia 29, 30 e 31 empurra a visita para o mês seguinte e desalinha o contrato inteiro.
- Contrato sem `end_date` gera até o limite pedido, nunca infinitamente.
- Este Service não grava nada. Ele é a fonte do cálculo, e a Task 9.4 é quem materializa.

### Critérios de aceitação

- [ ] Contrato mensal de 12 meses gera 12 datas
- [ ] Contrato iniciado em 31/01 com visita mensal gera 28/02 (ou 29/02 em ano bissexto), não 03/03
- [ ] Contrato quinzenal gera datas a cada 15 dias
- [ ] Contrato pontual devolve array vazio
- [ ] Contrato sem periodicidade devolve array vazio, sem exceção
- [ ] Nenhuma data ultrapassa `end_date`
- [ ] Contrato sem `end_date` respeita o limite informado
