# Task 15.6 - Layout do portal com identidade do tenant e telas de acesso

## Objetivo

Entregar a casca visual do portal com logo e cores da empresa, mais as telas de login, convite e recuperação.

## Tipo

frontend-componente

## Arquivos a criar/modificar

- `resources/js/Portal/Layouts/PortalLayout.vue` -> criar
- `resources/js/Portal/Pages/Login.vue` -> criar
- `resources/js/Portal/Pages/DefinirSenha.vue` -> criar

## Contexto necessário (ler antes)

- `app/Models/Company.php` -> logo e dados visuais do tenant
- `resources/js/Layouts/AuthenticatedLayout.vue` -> referência de estrutura
- `.claude/skills/frontend-design-system/SKILL.md` -> tema e componentes
- `.claude/tasks/15/15.2.md` -> fluxos de acesso

## Skills necessárias

- `frontend-design-system`

## Especificação

### O que fazer

1. `PortalLayout.vue`: cabeçalho com o logo da empresa e o nome do cliente logado, navegação com Início, Visitas, Documentos, Contratos, Pendências, Faturas e Solicitações, e rodapé com os dados de contato da empresa.

2. Identidade do tenant por variáveis CSS definidas na raiz a partir das props: cor primária, cor de destaque e logo. Sem cor configurada, cai no verde do sistema. Nada de folha de estilo por tenant nem CSS gerado em tempo de execução, que abriria porta para injeção.

3. `Login.vue`: e-mail e senha, logo da empresa acima, link de esqueci a senha. A tela deixa claro de qual empresa é o portal: o cliente pode ser atendido por mais de uma.

4. `DefinirSenha.vue`: usada no convite e na recuperação, com regra de senha visível antes de digitar e confirmação. Token expirado mostra a tela de link vencido, com a ação de pedir novo convite.

5. Menu em barra inferior no celular e lateral no computador. O cliente acessa o portal principalmente do celular.

6. Sem nenhum link para o sistema interno, e sem menção à plataforma. O portal é da empresa, na percepção do cliente.

### Regras de negócio aplicáveis

- A identidade é do tenant, não da plataforma. O cliente final não conhece a plataforma e não precisa conhecer.
- Cor vinda do banco entra apenas como valor de variável CSS, validada como cor hexadecimal. Interpolar valor do banco em CSS sem validar é injeção.
- Sem emoji.
- Contraste conferido: o portal é usado por gente que não escolheu o sistema e não vai pedir ajuda, vai desistir.

### Critérios de aceitação

- [ ] O portal exibe logo e cores da empresa
- [ ] Empresa sem cor configurada usa o verde padrão
- [ ] Cor inválida no banco não quebra a página nem injeta CSS
- [ ] Login mostra de qual empresa é o portal
- [ ] Token expirado mostra a tela de link vencido
- [ ] Navegação inferior no celular, lateral no computador
- [ ] Nenhum link leva ao sistema interno
- [ ] `npm run build` sem erro

## Teste esperado

- Comando: `npm run build`
- Verificação manual: abrir o portal de dois tenants diferentes e conferir as identidades
