# Task 2.16 - Teste do escopo do técnico e da regra do último administrador

## Objetivo
Cobrir por teste as duas regras de negócio do plano que não são simples middleware:
técnico limitado às próprias OS e empresa que nunca fica sem administrador ativo.

## Especificação

### O que fazer
`AcessoTecnicoTest`:
1. Técnico A vinculado a usuário A, técnico B a usuário B, uma OS para cada.
2. Usuário A na listagem `/work-orders` vê a OS dele e não vê a do B.
3. Usuário A recebe 403 em `/work-orders/{id_do_B}`.
4. Usuário com papel `tecnico` e sem técnico vinculado vê listagem vazia, não a lista completa.
5. Administrador vê as duas OS.
6. OS atribuída pela pivot `work_order_technicians` (e não por `technician_id`)
   também aparece para o técnico correspondente.

`GestaoUsuariosTest`:
1. Desativar o último administrador ativo devolve erro e mantém o usuário ativo.
2. Com dois administradores, desativar um funciona.
3. Trocar o papel do último administrador para `leitura` devolve erro.
4. Usuário desativado tenta logar e é rejeitado com mensagem em português.
5. Usuário sem permissão `usuario-ver` recebe 403 em `/settings/users`.

### Regras de negócio aplicáveis
- `RefreshDatabase` com o banco `testing` (MySQL).
- Se faltar factory para `WorkOrder` ou `Technician`, criar o registro direto com
  `create()`, sem inventar factory nova fora do escopo.

### Critérios de aceitação
- [ ] `php artisan test --filter=AcessoTecnicoTest` passa
- [ ] `php artisan test --filter=GestaoUsuariosTest` passa
- [ ] Os testes falham se a verificação de dono da OS for removida
