# Task 2.20 - Remover rotas de resource que apontam para métodos inexistentes

## Objetivo
Três `Route::resource` financeiros registram ações cujos métodos não existem no
controller. Hoje elas respondem 500 para quem tem permissão, e agora que estão
protegidas ficou claro que são rotas mortas. Restringir cada resource ao que o
controller de fato implementa.

## Tipo
backend-endpoint

## Arquivos a criar/modificar
- `routes/web.php` -> modificar (apenas os três resources financeiros)

## Contexto necessário (ler antes)
- `routes/web.php` -> bloco financeiro, já protegido por permissão
- `app/Http/Controllers/PaymentDetailController.php` -> métodos existentes: `store`, `show`, `update`, `destroy`
- `app/Http/Controllers/FinancialEntryController.php` -> métodos existentes: `index`, `store`, `show`, `update`, `destroy`
- `app/Http/Controllers/FinancialWithdrawalController.php` -> métodos existentes: `index`, `store`, `update`, `destroy`

## Skills necessárias
- `.claude/skills/laravel-arquitetura/SKILL.md`
- `.claude/skills/permissoes-e-multitenancy/SKILL.md`

## Especificação

### O que fazer
1. `payment-details` -> `->only(['store', 'show', 'update', 'destroy'])`
2. `financial-entries` -> `->only(['index', 'store', 'show', 'update', 'destroy'])`
3. `financial-withdrawals` -> `->only(['index', 'store', 'update', 'destroy'])`
4. Ajustar os `middlewareFor` de cada um para citar apenas as ações que
   permaneceram. `middlewareFor` de ação removida é ruído e engana quem lê.
5. Antes de remover, confirmar com `grep` que o frontend não chama nenhuma dessas
   rotas (`route('payment-details.index')`, `/financial-withdrawals/create`, e
   equivalentes). Se alguma estiver em uso, **não remova** e reporte: significa
   que a tela chama endpoint quebrado e o conserto é outro.

### Regras de negócio aplicáveis
- Isso remove rota que hoje só produz erro 500. Nenhum comportamento válido se perde.
- Não alterar controller nenhum nesta task.

### Critérios de aceitação
- [ ] `php artisan route:list --path=payment-details` não lista mais `index`, `create` nem `edit`
- [ ] Nenhuma rota financeira restante aponta para método inexistente
- [ ] Nenhuma referência do frontend quebrou (conferido por grep antes de remover)
- [ ] `php artisan test` continua passando

## Teste esperado
- Comando: `php artisan route:list --path=financial` e `--path=payment`
- Verificação manual: as telas financeiras continuam funcionando

## Estimativa
baixa - ~20 linhas alteradas | 1 arquivo
