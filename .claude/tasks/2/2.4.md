## Especificação

### O que fazer
1. Migration de **estrutura apenas**:
   - `users.is_active` boolean, `default(true)`, `after('email')`. Default true
     garante que todo usuário existente continua entrando no sistema depois do deploy.
   - `technicians.user_id` unsignedBigInteger nullable, FK para `users.id` com
     `nullOnDelete()`, index. Nullable porque hoje existem técnicos sem usuário
     (4 no banco local) e o vínculo é opcional.
   - `down()` remove a FK antes da coluna.
2. `User`: `is_active` em `$fillable` e cast `boolean`; relação
   `technician(): HasOne` para `Technician::class, 'user_id'`; método
   `ehTecnico(): bool` que devolve `$this->hasRole('tecnico')`.
3. `Technician`: `user_id` em `$fillable`; relação `user(): BelongsTo`.
4. Nenhum backfill de dado nesta task. O vínculo dos técnicos existentes é a Task 2.5.

### Regras de negócio aplicáveis
- Sistema em produção: coluna nova com default seguro, nada de `NOT NULL` sem default.
- Um usuário se liga a no máximo um técnico. Aplicar `unique` em `technicians.user_id`
  ignorando nulos (MySQL permite múltiplos NULL em índice unique).

### Critérios de aceitação
- [ ] `php artisan migrate --path=database/migrations/[arquivo]` roda sem erro

- [ ] Usuário existente fica com `is_active = 1` após a migration
