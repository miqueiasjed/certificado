# Task 2.18 - Dashboard não entrega dado financeiro a quem não pode ver

## Objetivo
O `DashboardController` monta `financialStats` (entradas, saídas e resultado do
mês) e envia para qualquer usuário autenticado. Técnico e papel `leitura` recebem
o faturamento na prop do Inertia, mesmo com as rotas financeiras já bloqueadas.

## Tipo
backend-endpoint

## Arquivos a criar/modificar
- `app/Http/Controllers/DashboardController.php` -> modificar

## Contexto necessário (ler antes)
- `app/Http/Controllers/DashboardController.php` -> método `index`, montagem de `financialStats`
- `app/Console/Commands/SyncPermissions.php` -> nome exato da permissão `financeiro-ver`

## Skills necessárias
- `.claude/skills/permissoes-e-multitenancy/SKILL.md`
- `.claude/skills/laravel-arquitetura/SKILL.md`

## Especificação

### O que fazer
1. Calcular e enviar `financialStats` apenas quando
   `$request->user()->can('financeiro-ver')`. Sem a permissão, a prop vai como
   `null`, e as consultas de soma nem chegam a rodar.
2. Fazer o mesmo com qualquer outro dado do dashboard que revele dinheiro
   (conferir o método inteiro, não só `financialStats`).
3. A rota do dashboard continua sem middleware de permissão: todo usuário
   autenticado entra, e o que ele enxerga é decidido aqui.

### Regras de negócio aplicáveis
- A rota não pode passar a exigir permissão: isso deixaria o técnico sem tela
  inicial.
- Não alterar o layout nem o contrato das demais props.

### Critérios de aceitação
- [ ] Usuário com papel `tecnico` recebe `financialStats = null` no dashboard
- [ ] Usuário com papel `financeiro` e administrador continuam recebendo os números
- [ ] As somas do financeiro não são executadas para quem não tem a permissão
- [ ] `php artisan test` continua passando

## Teste esperado
- Comando: `php artisan test`
- Verificação manual: via tinker, montar a resposta do dashboard para um usuário `tecnico` e conferir a prop

baixa - ~25 linhas | 1 arquivo
