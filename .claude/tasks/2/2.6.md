# Task 2.6 - Middleware nas rotas financeiras (crítico)

financeiro, fluxo de caixa, entradas, saídas, detalhes de pagamento e informação

## Especificação

### O que fazer
Envolver as rotas financeiras em grupos com `middleware('permission:...')`. Mapa
obrigatório:

| Rota | Middleware |
|---|---|
| `GET /financial-dashboard` | `permission:financeiro-ver` |
| `GET /cash-flow`, `/cash-flow/stats` | `permission:financeiro-ver` |
| `GET /cash-flow/export` | `permission:financeiro-exportar` |
| `financial-entries` index/show/stats | `permission:financeiro-ver` |
| `financial-entries` create/store | `permission:financeiro-lancamento-criar` |
| `financial-entries` edit/update | `permission:financeiro-lancamento-editar` |
| `financial-entries` destroy | `permission:financeiro-lancamento-excluir` |
| `financial-withdrawals` index/show/stats | `permission:financeiro-ver` |
| `financial-withdrawals` create/store | `permission:financeiro-saida-criar` |
| `financial-withdrawals` edit/update | `permission:financeiro-saida-editar` |
| `financial-withdrawals` destroy | `permission:financeiro-saida-excluir` |
| `payment-details` index/show, `/work-orders/{workOrder}/payment-details` | `permission:pagamento-ver` |
| `payment-details` store, `financial-entries.create-from-payment` | `permission:pagamento-registrar` |
| `payment-details` update | `permission:pagamento-editar` |
| `payment-details` destroy | `permission:pagamento-excluir` |
| `payment-details.reopen` | `permission:pagamento-reabrir` |
| `work-orders.financial-info.update` | `permission:pagamento-editar` |

Para os `Route::resource`, usar o encadeamento por ação em vez de reescrever cada
rota à mão, por exemplo:

```php
Route::resource('financial-entries', FinancialEntryController::class)
    ->middleware([
        'index' => 'permission:financeiro-ver',
        'show' => 'permission:financeiro-ver',
        'create' => 'permission:financeiro-lancamento-criar',
        'store' => 'permission:financeiro-lancamento-criar',
        'edit' => 'permission:financeiro-lancamento-editar',
        'update' => 'permission:financeiro-lancamento-editar',
        'destroy' => 'permission:financeiro-lancamento-excluir',
    ]);
```

Atenção: `financial-entries/stats` e `financial-withdrawals/stats` precisam ser
declaradas **antes** do `Route::resource` correspondente, senão `{financial_entry}`
captura a string `stats`. Conferir a ordem atual e preservar o comportamento.

### Regras de negócio aplicáveis
- Rota financeira sem middleware é bug. Nenhuma pode ficar de fora.
- Não alterar controller nem service nesta task. Só rota.
- Registrar no relatório final, sem alterar: `GET /service-orders/{workOrder}/receipt`
  (linha 43) está fora de qualquer middleware, inclusive `auth`, e expõe recibo por
  ID sequencial. Corrigir isso quebraria links já enviados a clientes, então é
  decisão do usuário e não entra nesta task.

### Critérios de aceitação
- [ ] Usuário com papel `tecnico` recebe 403 em `/financial-dashboard`, `/cash-flow`, `/financial-entries` e `/financial-withdrawals`
- [ ] Usuário com papel `financeiro` acessa as quatro normalmente
- [ ] Usuário com papel `comercial` recebe 403 em todas as rotas da tabela
- [ ] Nenhuma rota financeira ficou sem middleware (conferir com `php artisan route:list --path=financial` e `--path=payment`)
