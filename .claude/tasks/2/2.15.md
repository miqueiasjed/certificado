# Task 2.15 - Teste de acesso negado por papel nas rotas financeiras

## Objetivo
Garantir por teste automatizado que papel sem permissão financeira recebe 403 em
cada rota de dinheiro, uma a uma.

## Tipo
teste

## Arquivos a criar/modificar
- `tests/Feature/AcessoFinanceiroTest.php` -> criar
- `database/factories/UserFactory.php` -> modificar se necessário (estado com papel)

## Contexto necessário (ler antes)
- `tests/Feature/RotinasAgendadasTest.php` -> padrão de teste do projeto e uso do banco `testing`
- `routes/web.php` -> rotas financeiras após a Task 2.6
- `database/seeders/RolesAndPermissionsSeeder.php` -> papéis disponíveis
- `.claude/progress.txt` -> "SQLite não roda as migrations deste projeto", o banco de teste é MySQL `testing`

## Skills necessárias
- `.claude/skills/laravel-arquitetura/SKILL.md`
- `.claude/skills/permissoes-e-multitenancy/SKILL.md`

## Especificação

### O que fazer
1. `setUp` roda o `RolesAndPermissionsSeeder` e cria um usuário por papel.
2. Um `dataProvider` (ou array iterado) com todas as rotas financeiras protegidas:
   `/financial-dashboard`, `/cash-flow`, `/cash-flow/stats`, `/cash-flow/export`,
   `/financial-entries`, `/financial-withdrawals`, `/payment-details`.
3. Para cada rota, asserção de **403** com papel `tecnico`, `comercial` e `leitura`,
   e de **200** (ou redirect legítimo) com `financeiro` e `administrador`.
4. Teste separado para as ações de escrita: `POST /financial-entries`,
   `DELETE /financial-entries/{id}`, `POST /payment-details/{id}/reopen`, cada uma
   negada para quem não tem a permissão específica, inclusive para o papel
   `financeiro` quando a permissão não estiver na lista dele.
5. Teste de regressão explícito: usuário sem papel nenhum recebe 403, não 200.

### Regras de negócio aplicáveis
- Usar `RefreshDatabase` com o banco `testing` (MySQL), como no teste existente.
- O teste falha se alguém acrescentar rota financeira sem middleware: incluir uma
  asserção que percorre `Route::getRoutes()` filtrando por `financial|cash-flow|payment`
  e exige middleware de permissão em todas.

### Critérios de aceitação
- [ ] `php artisan test --filter=AcessoFinanceiroTest` passa
- [ ] Remover o middleware de uma rota financeira faz o teste falhar
- [ ] Nenhum teste depende de dado do seeder de demonstração

## Teste esperado
- Comando: `php artisan test --filter=AcessoFinanceiroTest`

média - ~160 linhas | 1 a 2 arquivos
