# Task 2.9 - Compartilhar papéis e permissões com o frontend

## Objetivo
Expor no Inertia os papéis e as permissões do usuário autenticado, para que menu e
ações possam reagir a eles.

## Tipo
backend-endpoint

## Arquivos a criar/modificar
- `app/Http/Middleware/HandleInertiaRequests.php` -> modificar

## Contexto necessário (ler antes)
- `app/Http/Middleware/HandleInertiaRequests.php` -> método `share()` atual
- `.claude/skills/permissoes-e-multitenancy/SKILL.md`

## Skills necessárias
- `.claude/skills/laravel-arquitetura/SKILL.md`
- `.claude/skills/permissoes-e-multitenancy/SKILL.md`

## Especificação

### O que fazer
No `share()`, dentro de `auth.user`, acrescentar:

- `papeis` -> `$request->user()->getRoleNames()` (array de strings)
- `permissoes` -> `$request->user()->getAllPermissions()->pluck('name')` (array de strings)
- `ehTecnico` -> booleano, `hasRole('tecnico')`

Envolver o cálculo em `fn () => ...` (lazy) só se o custo justificar; a lista é
pequena e o Spatie já mantém cache, então valor direto é aceitável.

### Regras de negócio aplicáveis
- O frontend usa isso para esconder botão. **Não** é controle de acesso: quem
  protege é o middleware da rota. Esconder botão sem middleware é falso controle.
- Usuário não autenticado continua devolvendo `auth.user = null`, sem os campos novos.

### Critérios de aceitação
- [ ] Uma página Inertia qualquer recebe `auth.user.permissoes` com as permissões do papel
- [ ] Usuário com papel `tecnico` traz `ehTecnico = true` e não traz `financeiro-ver` na lista
- [ ] Nenhuma requisição quebra quando o usuário não tem papel algum (array vazio, não erro)
