# Task 8.2 - Catálogo compartilhado dos cadastros de apoio e regulatórios

## Objetivo

Declarar em fonte única o conteúdo inicial que todo tenant novo recebe: tipos de evento, tipos de isca, tipos de serviço, unidades e os cadastros regulatórios.

## Tipo

backend-estrutura

## Arquivos a criar/modificar

- `app/Support/CatalogoInicialDoTenant.php` -> criar
- `database/seeders/CatalogoInicialSeeder.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/EventType.php`, `BaitType.php`, `ServiceType.php` -> estrutura dos cadastros de apoio
- `app/Models/ActiveIngredient.php`, `ChemicalGroup.php`, `Antidote.php`, `OrganRegistration.php` -> cadastros regulatórios
- Dados do tenant 1 em produção -> é a melhor fonte do que uma dedetizadora realmente usa
- `app/Support/CatalogoDeModulos.php` -> padrão de catálogo em método estático (Plano 6)

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

1. `App\Support\CatalogoInicialDoTenant` com um método por grupo, cada um devolvendo array de arrays prontos para criação:
   - `tiposDeEvento()` -> os tipos que o setor usa (consumo de isca, isca intacta, isca ausente, dispositivo danificado, praga capturada, ...)
   - `tiposDeIsca()`
   - `tiposDeServico()` -> desinsetização, desratização, descupinização, sanitização de caixa d'água, controle de pombos
   - `unidades()`
   - `principiosAtivos()`, `gruposQuimicos()`, `antidotos()`, `registrosEmOrgao()` -> o conjunto regulatório de partida

2. O conteúdo sai dos dados reais do tenant 1, exportados e revisados, não inventados. Registrar no cabeçalho da classe de onde veio.

3. `CatalogoInicialSeeder`: aplica o catálogo em um tenant informado, dentro de `TenantAtual::comTenant()`, com `firstOrCreate` por chave natural (nome ou slug) para ser idempotente.

4. Onde houver dependência entre cadastros (princípio ativo aponta grupo químico e antídoto), semear na ordem correta e resolver as referências por nome.

### Regras de negócio aplicáveis

- Empresa nova que chega sem esses cadastros encontra um sistema inutilizável e desiste na primeira sessão. Este catálogo é o que decide se o onboarding funciona.
- Os cadastros regulatórios são **copiados** para o tenant, não compartilhados por referência. A partir da cópia, cada empresa edita o próprio sem afetar as outras, que é a regra do PRD.
- Seeder idempotente: rodar duas vezes não duplica.
- Nenhum dado do tenant 1 é movido ou alterado. O catálogo é uma cópia declarada em código.

### Critérios de aceitação

- [ ] O catálogo cobre os quatro cadastros de apoio e os quatro regulatórios
- [ ] `php artisan db:seed --class=CatalogoInicialSeeder` aplicado a um tenant novo cria tudo com o `company_id` certo
- [ ] Rodar duas vezes não duplica
- [ ] Princípio ativo criado já aponta grupo químico e antídoto corretos
- [ ] Nenhum registro do tenant 1 foi alterado
- [ ] A origem dos dados está registrada no cabeçalho da classe

## Teste esperado

- Comando: `php artisan db:seed --class=CatalogoInicialSeeder` em um tenant de teste, duas vezes
- Verificação manual: comparar a contagem por cadastro entre o tenant novo e o esperado do catálogo
