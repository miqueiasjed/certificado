# Task 5.3 - Área do super admin com acesso separado

## Objetivo

Criar o middleware, o prefixo de rota e o layout de acesso da área administrativa da plataforma, isolada do login das empresas.

## Tipo

backend-endpoint

## Arquivos a criar/modificar

- `app/Http/Middleware/EnsurePlatformAdmin.php` -> criar
- `bootstrap/app.php` -> modificar (registrar o alias do middleware)
- `routes/web.php` -> modificar (grupo `/plataforma`)

## Contexto necessário (ler antes)

- `routes/web.php` -> grupos e middleware existentes, inclusive os do Plano 2
- `bootstrap/app.php` -> registro de middleware
- `app/Http/Controllers/AuthController.php` -> fluxo de login atual
- `app/Support/TenantAtual.php` -> `semEscopo()`, usado pelo super admin

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

1. `EnsurePlatformAdmin`: exige usuário autenticado com `is_platform_admin = true`; senão, 403. Ao passar, ativa o modo `TenantAtual::semEscopo()` para a requisição, para o painel enxergar todos os tenants.

2. Registrar o alias `platform.admin` em `bootstrap/app.php`.

3. Criar o grupo de rotas `Route::prefix('plataforma')->name('plataforma.')->middleware(['auth', 'platform.admin'])`, vazio nesta task. Os endpoints entram nas Tasks 5.7 e 5.8.

4. Decisão de autenticação: **mesmo formulário de login**, mesma tabela `users`, redirecionamento diferente após entrar. Um segundo guard com tabela própria dobraria o custo de manutenção de sessão, recuperação de senha e auditoria sem ganho real. O isolamento vem do middleware, não de um login separado. Registrar essa decisão como comentário no grupo de rotas.

5. Após o login, redirecionar `is_platform_admin` para `/plataforma`, e os demais para o dashboard atual.

6. O super admin, ao acessar a área das empresas sem ter assumido um tenant, recebe mensagem clara pedindo que escolha um tenant (a ação em si é a Task 5.5).

### Regras de negócio aplicáveis

- `semEscopo()` ativo **apenas** dentro do prefixo `/plataforma`. Vazar esse modo para a área das empresas anula todo o isolamento do Plano 4.
- Usuário comum acessando `/plataforma/*` recebe 403 e o acesso fica registrado (o `AccessLog` do Plano 3 já cobre login; tentativa de acesso negado à plataforma vale registro próprio, com `evento = plataforma_negada`).
- Nenhuma tela nesta task. Só a fundação de acesso.

### Critérios de aceitação

- [ ] Usuário sem `is_platform_admin` recebe 403 em qualquer rota `/plataforma/*`
- [ ] Super admin autenticado passa e enxerga além do próprio tenant
- [ ] O modo `semEscopo` não vaza para requisições fora do prefixo
- [ ] Login de super admin redireciona para `/plataforma`
- [ ] Login de usuário comum continua indo para o dashboard atual
- [ ] `php artisan test` continua passando

## Teste esperado

- Comando: `php artisan test`
- Verificação manual: marcar um usuário com `is_platform_admin = true`, entrar e conferir o redirecionamento; entrar com outro e conferir o 403
