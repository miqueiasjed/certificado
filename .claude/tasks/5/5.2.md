# Task 5.2 - Migration e model de uso por tenant

## Objetivo

Criar a tabela que guarda o uso apurado de cada tenant por período, para o painel de uso e para os limites do Plano 6.

## Tipo

backend-estrutura

## Arquivos a criar/modificar

- `database/migrations/*_create_tenant_usages_table.php` -> criar
- `app/Models/TenantUsage.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/Plan.php` -> limites definidos na Task 5.1
- `app/Models/ScheduledTaskRun.php` -> model de registro periódico, referência de estilo
- `app/Support/BusinessDate.php` -> apuração por período usa o fuso do negócio

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

1. Tabela `tenant_usages`: `id`, `company_id` (FK, `cascadeOnDelete` aqui é aceitável: apuração é derivada, não é dado do cliente), `referencia` (string `YYYY-MM`), `usuarios` (int), `clientes` (int), `ordens_servico` (int), `certificados` (int), `armazenamento_mb` (int), `apurado_em` (timestamp), timestamps. Unique composto `[company_id, referencia]`.

2. `app/Models/TenantUsage.php`: fillable, casts, relação `company()`, scope `doPeriodo(string $referencia)`.

3. **Sem** a trait `BelongsToCompany`: a tabela é lida pelo super admin, que precisa ver todos os tenants. Classificar em `TABELAS_FORA_DO_ESCOPO` com esse motivo. O tenant que quiser ver o próprio uso (Plano 6) filtra explicitamente.

4. Índice em `referencia` para o painel geral, que agrupa por período.

### Regras de negócio aplicáveis

- `referencia` no formato `YYYY-MM` calculado no fuso do negócio. Apuração feita à meia-noite UTC do dia 1 cairia no mês anterior em Brasília.
- Unique composto garante uma apuração por tenant por mês. Reapurar sobrescreve, não duplica.
- `armazenamento_mb` é o campo mais caro de calcular (soma de arquivos de foto). Guardar apurado, nunca calcular sob demanda no painel.

### Critérios de aceitação

- [ ] `php artisan migrate` cria a tabela com o unique composto
- [ ] Gravar duas apurações do mesmo tenant e mês falha por unique
- [ ] `TenantUsage` não usa `BelongsToCompany`
- [ ] `EscopoDeEmpresaTest` continua passando
- [ ] `migrate:rollback` desfaz sem erro

## Teste esperado

- Comando: `php artisan migrate && php artisan test --filter=EscopoDeEmpresaTest`
- Verificação manual: inserir uma apuração no tinker e conferir o unique
