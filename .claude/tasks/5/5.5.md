# Task 5.5 - Assumir tenant para suporte, com registro em auditoria

## Objetivo

Permitir que o super admin opere dentro de um tenant para dar suporte, com aviso visível, saída em um clique e registro de entrada e saída.

## Tipo

backend-endpoint

## Arquivos a criar/modificar

- `app/Services/AssumirTenantService.php` -> criar
- `app/Http/Controllers/Plataforma/AssumirTenantController.php` -> criar
- `routes/web.php` -> modificar
- `app/Http/Middleware/HandleInertiaRequests.php` -> modificar (compartilhar o estado de suporte)

## Contexto necessário (ler antes)

- `app/Support/TenantAtual.php` -> `definir()` e `id()`
- `app/Models/AccessLog.php` -> eventos `tenant_assumido` e `tenant_liberado`, declarados na Task 3.1
- `app/Http/Middleware/HandleInertiaRequests.php` -> o que já é compartilhado com o frontend
- `app/Http/Middleware/EnsurePlatformAdmin.php` -> criado na Task 5.3

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

1. `AssumirTenantService`:
   - `assumir(User $superAdmin, Company $empresa): void` -> grava na sessão `tenant_assumido_id` e `tenant_assumido_nome`, registra `AccessLog` com `evento = tenant_assumido` e `detalhes` contendo id e nome da empresa
   - `liberar(User $superAdmin): void` -> limpa a sessão e registra `evento = tenant_liberado`
   - `assumidoAtualmente(): ?array` -> id e nome, ou null

2. A resolução do tenant precisa considerar a sessão: em `TenantAtual::id()`, o valor de sessão `tenant_assumido_id` tem precedência sobre `auth()->user()->company_id`, **apenas** quando o usuário é `is_platform_admin`. Ajustar `TenantAtual` para consultar a sessão nesse caso, com o teste de `is_platform_admin` explícito.

3. Endpoints, dentro do grupo `/plataforma`:
   - `POST /plataforma/tenants/{company}/assumir` -> assume e redireciona para o dashboard das empresas
   - `POST /plataforma/liberar` -> libera e volta para `/plataforma`

4. Em `HandleInertiaRequests::share()`, acrescentar `suporte` com `['ativo' => bool, 'empresa' => nome]`, para o frontend exibir a faixa de aviso (Task 5.9).

### Regras de negócio aplicáveis

- Toda entrada em tenant é acesso a dado de cliente e precisa ficar registrada. Sem registro, a funcionalidade não sobe.
- Enquanto está assumindo um tenant, o super admin opera como usuário daquele tenant e o escopo global se aplica normalmente. O modo `semEscopo` da Task 5.3 vale só no prefixo `/plataforma`.
- Saída em um clique, de qualquer tela. O botão fica na faixa de aviso, sempre visível.
- Sessão encerrada libera o tenant automaticamente, porque o valor vive na sessão.

### Critérios de aceitação

- [ ] Assumir um tenant grava `AccessLog` com `evento = tenant_assumido` e o id da empresa
- [ ] Liberar grava `tenant_liberado`
- [ ] Enquanto assumido, `TenantAtual::id()` devolve o id do tenant assumido
- [ ] Usuário comum não consegue assumir tenant algum (403)
- [ ] Usuário comum com sessão adulterada contendo `tenant_assumido_id` continua vendo apenas o próprio tenant
- [ ] O frontend recebe `suporte.ativo` e o nome da empresa
