# Task 31.4 - Frontend: parada de compromisso no roteiro e no mapa

## Objetivo

Mostrar a parada de compromisso na tela de roteiro e no mapa, distinta de
uma parada de OS, e permitir reordenar arrastando as duas juntas.

## Tipo

frontend-pagina

## Arquivos a criar/modificar

- `resources/js/Pages/Roteiros/Index.vue` -> modificar
- `resources/js/Components/MapaDeVisitas.vue` -> modificar

## Contexto necessário (ler antes)

- `resources/js/Pages/Roteiros/Index.vue` (arquivo inteiro) -> lista de
  paradas, drag-and-drop de reordenação, chamada a `PUT
  /roteiros/{id}/ordem`
- `resources/js/Components/MapaDeVisitas.vue` (arquivo inteiro) -> como cada
  parada vira marcador no mapa, o que `temCoordenadaBoa()` verifica
- `.claude/skills/frontend-design-system/SKILL.md`

## Skills necessárias

- `frontend-design-system`

## Especificação

### O que fazer

1. Em `Roteiros/Index.vue`, todo cartão de parada passa a checar
   `parada.tipo_item`. Quando for `'compromisso'`: cor distinta da usada
   para OS (mesma paleta já adotada na Agenda para compromisso, Task 30.5,
   para o usuário reconhecer o mesmo padrão visual nas duas telas), mostra
   `parada.compromisso_titulo` no lugar do nome do cliente quando não há
   cliente vinculado, e um rótulo curto do `parada.compromisso_tipo`.

2. O payload que a reordenação por arrastar-e-soltar envia para `PUT
   /roteiros/{id}/ordem` muda de lista de `work_order_id` para lista de
   string `"os:{id}"`/`"compromisso:{id}"` (contrato definido na Task
   31.3): montar essa string a partir de `parada.tipo_item` e
   `parada.work_order_id`/`parada.route_stop_id` (usar o id certo conforme
   o tipo).

3. Em `MapaDeVisitas.vue`, o marcador de uma parada de compromisso usa ícone
   ou cor distintos do marcador de OS (mesmo critério do item 1). O texto do
   popup/tooltip mostra `compromisso_titulo` quando não há cliente.
   `paradasSemCoordenada` (lista de paradas sem coordenada boa) já funciona
   igual para as duas origens, sem mudança de lógica: só o texto do item da
   lista precisa diferenciar OS de compromisso.

### Regras de negócio aplicáveis

- Nenhuma regressão visual ou funcional na parada de OS existente.
- Nenhuma formatação de data/hora com `toLocaleDateString`: usar os
  utilitários do projeto.

### Critérios de aceitação

- [ ] Parada de compromisso aparece na lista do roteiro, visualmente
      distinta de OS
- [ ] Reordenar arrastando funciona com lista mista (OS e compromisso
      juntos)
- [ ] Parada de compromisso aparece no mapa com marcador distinto
- [ ] Paradas de OS continuam renderizando exatamente como antes

## Teste esperado

- Comando: nenhum (sem suíte de teste JS no projeto)
- Verificação manual: abrir `/roteiros/painel`, escolher um técnico com OS e
  compromisso no mesmo dia, conferir lista e mapa, reordenar arrastando e
  conferir que a nova ordem persiste
