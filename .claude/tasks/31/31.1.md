# Task 31.1 - RouteStop aceita compromisso

## Objetivo

Dar a `RouteStop` a relação com `Compromisso`, espelhando a que já existe
com `WorkOrder`, agora que a coluna `compromisso_id` já existe no banco.

## Tipo

backend-estrutura

## Arquivos a criar/modificar

- `app/Models/RouteStop.php` -> modificar

## Contexto necessário (ler antes)

- `database/migrations/2026_08_10_100002_add_compromisso_to_route_stops_table.php`
  -> a coluna já existe, com o porquê de cada decisão (nullable, cascade,
  unique própria)
- `app/Models/Compromisso.php` (Task 30.1 do Plano 30, precisa estar
  concluída)
- `app/Models/RouteStop.php` (estado atual, só a relação `workOrder()`)

## Skills necessárias

- `laravel-arquitetura`

## Especificação

### O que fazer

1. Acrescentar `'compromisso_id'` a `$fillable`.
2. Nova relação `compromisso(): BelongsTo` ->
   `$this->belongsTo(Compromisso::class)`, no mesmo padrão de `workOrder()`.
3. Método de conveniência `eDeCompromisso(): bool` -> `$this->compromisso_id
   !== null`. Existe para os pontos de chamada do `RouteService` (Task 31.2)
   e do `RouteController` (Task 31.3) não repetirem a mesma comparação em
   vários lugares com nomes ligeiramente diferentes.
4. Atualizar o docblock da classe: a parada agora representa **uma OS OU um
   compromisso avulso**, nunca os dois ao mesmo tempo (a regra de
   exclusividade é garantida pelo `RouteService`, não pelo `Model` nem pelo
   banco - documentar isso aqui, referenciando onde a regra realmente mora).

### Regras de negócio aplicáveis

- `work_order_id` e `compromisso_id` são mutuamente exclusivos: exatamente
  um dos dois preenchido por parada. Esta task só registra a relação; **não**
  é o lugar de validar a exclusividade (isso é `RouteService`, Task 31.2).

### Critérios de aceitação

- [ ] `RouteStop::compromisso()` devolve o `Compromisso` da parada quando
      `compromisso_id` está preenchido
- [ ] `RouteStop::eDeCompromisso()` devolve `true`/`false` corretamente
- [ ] Nenhuma migration nova: a coluna já existe
