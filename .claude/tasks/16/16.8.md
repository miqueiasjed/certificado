# Task 16.8 - Testes de rota pública, agendamento e pesquisa

## Objetivo

Cobrir o que é arriscado neste plano: rota aberta à internet e indicador que pode ser contaminado.

## Tipo

teste

## Arquivos a criar/modificar

- `tests/Feature/AgendamentoPublicoTest.php` -> criar
- `tests/Feature/AppointmentRequestTest.php` -> criar
- `tests/Feature/SatisfactionSurveyTest.php` -> criar

## Contexto necessário (ler antes)

- `.claude/tasks/16/16.3.md` -> proteções da rota pública
- `.claude/tasks/16/16.4.md` -> regras de confirmação
- `.claude/tasks/16/16.5.md` -> regras de envio e de indicador
- `routes/publico.php` -> rotas expostas sem autenticação

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`
- `datas-timezone`

## Especificação

### O que fazer

1. `AgendamentoPublicoTest`:
   - slug válido abre a página; inexistente devolve 404; com agendamento desligado devolve 404;
   - quarto pedido na mesma hora pelo mesmo IP é recusado;
   - campo armadilha preenchido não cria registro e responde como sucesso;
   - envio em menos de 3 segundos é recusado;
   - a grade não contém contagem de vagas nem nome de técnico (percorrer o JSON);
   - o pedido não cria OS;
   - **percorrer todas as rotas de `routes/publico.php` e afirmar que nenhuma exige nem expõe dado autenticado**.

2. `AppointmentRequestTest`:
   - confirmar cria a OS e vincula;
   - confirmar em período lotado devolve 422;
   - confirmar pedido já respondido devolve 422;
   - recusar sem motivo devolve 422;
   - pedido de um tenant não é visível no outro;
   - sem permissão devolve 403.

3. `SatisfactionSurveyTest`:
   - a rotina envia das OS concluídas ontem, no fuso do negócio (fixar o instante);
   - cliente que recusou o canal não recebe;
   - cliente que respondeu há 10 dias não recebe;
   - token válido responde uma vez; segunda resposta é recusada;
   - token expirado é recusado;
   - token de outro tenant não resolve nada;
   - nota 1 marca pendência e enfileira aviso;
   - corte com 2 respostas omite a média;
   - a página do token não expõe nenhum outro dado do cliente (percorrer o JSON).

### Regras de negócio aplicáveis

- Rota pública é a maior superfície de ataque criada até aqui no roteiro. O teste que enumera as rotas do arquivo é obrigatório.
- O teste de token que não vaza dado protege contra o erro mais provável: alguém acrescentar o histórico do cliente na página de pesquisa por conveniência.
- Teste de fuso fixa o instante.

### Critérios de aceitação

- [ ] Os três arquivos passam
- [ ] O teste que enumera as rotas públicas está presente
- [ ] Os testes de limite de taxa e de campo armadilha estão presentes
- [ ] O teste de token que não vaza dado percorre o JSON
- [ ] A suíte continua verde

## Teste esperado

- Comando: `php artisan test --filter="AgendamentoPublicoTest|AppointmentRequestTest|SatisfactionSurveyTest"`
- Verificação manual: não se aplica
