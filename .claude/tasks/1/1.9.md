## Especificação

### O que fazer

Em cada arquivo:

1. Localizar toda chamada a `toLocaleDateString`, `toLocaleString` e `toLocaleTimeString` aplicada a **data** e substituir pela função equivalente:
   - só o dia -> `formatarData`
   - dia com hora -> `formatarDataHora`
   - só a hora -> `formatarHora`
   - data por extenso -> `formatarDataExtensa`
2. Adicionar o import no `<script setup>`: `import { formatarData, formatarDataHora } from '@/utils/formatDate'` (importar apenas o que o arquivo usa).
3. Em `WorkOrderTabContent.vue`, conferir cada uma das 13 ocorrências separadamente: há mistura de data de execução (dia) com registro de evento (instante), e trocar uma pela outra muda o que o usuário lê.
4. Remover funções locais de formatação de data e as chamadas a elas.

### Regras de negócio aplicáveis

- Data de execução da OS entra em documento emitido: erro de um dia é regressão.
- Hora de início e fim de execução é instante e vai por `formatarDataHora` ou `formatarHora`, com conversão de fuso. Data agendada é dia e não converte.
- Não tocar em formatação de moeda.
- Não alterar layout, classe CSS nem texto.

### Critérios de aceitação

- [ ] `grep -rn "toLocaleDateString\|toLocaleTimeString" resources/js/Pages/WorkOrders resources/js/Pages/ServiceOrders resources/js/Pages/Budgets resources/js/Components/WorkOrderTabContent.vue` não devolve nada
- [ ] As 13 ocorrências de `WorkOrderTabContent.vue` foram classificadas entre dia e instante, e a classificação está no retorno da task
- [ ] `npm run build` compila sem erro
- [ ] Nenhuma função local de formatação de data sobrou
