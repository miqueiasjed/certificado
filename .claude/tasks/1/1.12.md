## Especificação

### O que fazer

1. Em cada arquivo, substituir a chamada `toLocale*` que formata data pela função equivalente de `@/utils/formatDate` e adicionar o import correspondente.
2. Remover funções locais de formatação de data e as chamadas a elas.
3. Ao terminar, rodar a varredura final no projeto inteiro:
   ```
   grep -rn "toLocaleDateString\|toLocaleTimeString" resources/js
   ```
   O resultado deve ser vazio. Se sobrar algo, corrija no próprio arquivo e informe no retorno.
4. Rodar também:
   ```
   grep -rn "toLocaleString" resources/js
   ```
   As **únicas** ocorrências aceitas são as de moeda em `resources/js/app.js` e `resources/js/Composables/useMasks.js`. Qualquer outra é data e precisa ser trocada.

### Regras de negócio aplicáveis

- Nestas telas a data costuma ser registro de cadastro (`created_at`, validade de registro de órgão), portanto instante ou dia conforme o campo. Confirme antes de escolher a função.
- Validade de registro no órgão competente entra em documento e em fiscalização: precisa exibir o dia correto.
- Não tocar em formatação de moeda.
- Não alterar layout, classe CSS nem texto.

### Critérios de aceitação

- [ ] `grep -rn "toLocaleDateString\|toLocaleTimeString" resources/js` devolve vazio no projeto inteiro
- [ ] `grep -rn "toLocaleString" resources/js` devolve apenas `app.js` e `useMasks.js`
- [ ] `npm run build` compila sem erro
- [ ] Nenhuma função local de formatação de data sobrou

## Teste esperado
