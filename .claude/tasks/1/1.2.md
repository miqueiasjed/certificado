## Especificação

### O que fazer

1. Migration criando `scheduled_task_runs`:

   | Coluna | Tipo | Observação |
   |---|---|---|
   | `id` | id | |
   | `task` | string(100) | assinatura do comando, ex.: `certificates:update-status` |
   | `started_at` | datetime | início da rodada |
   | `finished_at` | datetime nullable | preenchido no fim |
   | `status` | string(20) | `running`, `success` ou `failed` |
   | `duration_ms` | unsignedInteger nullable | duração da rodada |
   | `output` | text nullable | resumo ou mensagem de erro, truncado |
   | `timestamps` | | |

   Índices: `index(['task', 'started_at'])` e `index('status')`.

2. Model `ScheduledTaskRun` com:
   - `$fillable` com todas as colunas acima
   - `$casts`: `'started_at' => 'datetime'`, `'finished_at' => 'datetime'`
   - scope `scopeDaTarefa($query, string $task)`
   - scope `scopeUltimas($query, int $limite = 10)` ordenando por `started_at` desc

### Regras de negócio aplicáveis

- Tabela nova, sem dado existente: pode ir em deploy único, sem etapa de backfill.
- `started_at` e `finished_at` são instantes, portanto `datetime` gravado em UTC, com conversão só na exibição.
- Nenhuma lógica de negócio no model: só `$fillable`, `$casts` e scopes.
- `output` deve ser truncado por quem grava (Task 1.3), não pelo model.

### Critérios de aceitação

- [ ] `php artisan migrate` cria a tabela sem erro
- [ ] `php artisan migrate:rollback` remove a tabela sem erro
- [ ] Model tem casts de `datetime` declarados explicitamente
- [ ] Scopes funcionam encadeados: `ScheduledTaskRun::daTarefa('x')->ultimas(5)->get()`

## Teste esperado

- Comando: `php artisan migrate --pretend` e depois `php artisan migrate`
- Verificação: `php artisan tinker --execute="dump(App\Models\ScheduledTaskRun::daTarefa('teste')->ultimas(3)->toSql());"`
