# Task 1.4 - Comando de diagnóstico e instrução de cron

## Objetivo

Entregar um comando que mostra quando cada rotina rodou pela última vez e documentar no README o cron sem o qual nada disso executa.

## Tipo

backend-endpoint

## Arquivos a criar/modificar

- `app/Console/Commands/ShowRoutineStatus.php` -> criar
- `README.md` -> modificar

## Contexto necessário (ler antes)

- `app/Models/ScheduledTaskRun.php` -> criado na Task 1.2
- `app/Support/RotinasAgendadas.php` -> criado na Task 1.3, tem a constante `DIARIAS` com as quatro assinaturas e horários. **Use essa constante como fonte única**, não redeclare a lista
- `app/Listeners/RegistraExecucaoAgendada.php` -> criado na Task 1.3, é quem grava os registros
- `bootstrap/app.php` -> agendamento criado na Task 1.3
- `app/Console/Commands/UpdateCertificateStatus.php` -> padrão de comando do projeto

## Achados da Task 1.3 que esta task precisa tratar

1. Além de `running`, `success` e `failed`, existe um quarto status: **`skipped`**, gravado quando a trava `withoutOverlapping` barra a rodada. Trate `skipped` como "não rodou" no cálculo de atraso: ele não pode contar como execução bem-sucedida.
2. `CACHE_STORE=database` no ambiente local, e o store `database` usa a tabela `cache_locks` para a trava. Se o MySQL cair, a rotina morre no mutex, antes de qualquer código da aplicação. Registre esse alerta na seção do README.
3. O `.env` de produção precisa ser conferido: só o local foi verificado. Inclua isso na seção do README como item de checagem de deploy.

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

1. Criar comando `routines:status` que imprime uma tabela com uma linha por rotina agendada:

   | Rotina | Última execução | Status | Duração | Atrasada? |
   |---|---|---|---|---|

   - "Última execução" formatada em `d/m/Y H:i` no fuso do negócio (use `App\Support\BusinessDate`)
   - Rotina sem nenhum registro aparece como `nunca executou`
   - "Atrasada?" é `SIM` quando a última execução com sucesso tem mais de 48 horas, ou quando nunca executou
   - Linha atrasada ou com `status = failed` sai destacada com `$this->error()`; as demais com `$this->line()`

2. Código de saída: `Command::FAILURE` se qualquer rotina estiver atrasada ou falhada, `Command::SUCCESS` caso contrário. Isso permite plugar o comando em monitoramento externo.

3. Opção `--task=` para filtrar uma rotina específica.

4. No `README.md`, criar a seção **Rotinas agendadas** contendo:
   - A tabela das quatro rotinas com horário e o que cada uma faz
   - A linha de cron exata, com o caminho real do projeto:
     ```
     * * * * * cd /caminho/do/projeto && php artisan schedule:run >> /dev/null 2>&1
     ```
   - O aviso de que **sem esse cron nenhuma rotina executa**, que é a causa do bug de status hoje em produção
   - Como conferir: `php artisan routines:status`

### Regras de negócio aplicáveis

- A lista de rotinas do comando deve derivar de uma constante única, para não divergir do agendamento.
- Data exibida ao usuário sempre no fuso do negócio, nunca em UTC.
- Comando é só leitura: não altera nem cria registro em `scheduled_task_runs`.

### Critérios de aceitação

- [ ] `php artisan routines:status` roda em banco vazio e mostra `nunca executou` nas quatro linhas
- [ ] Após rodar uma rotina, a linha dela mostra data, hora e duração
- [ ] `--task=certificates:update-status` filtra corretamente
- [ ] Código de saída é 1 quando há rotina atrasada
- [ ] README traz a linha de cron e o aviso
