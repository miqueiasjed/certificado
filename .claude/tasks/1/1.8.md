# Task 1.8 - Substituir formatação de data: certificados e contratos

## Objetivo

Eliminar `toLocaleDateString` das telas de certificado e de contrato, passando a usar `resources/js/utils/formatDate.js`. São as telas em que o erro de um dia invalida documento emitido.

## Tipo

frontend-pagina

- `resources/js/Pages/Certificates/Show.vue` -> modificar (1)

- `resources/js/Pages/Contracts/Index.vue` -> modificar (2)
- `resources/js/Pages/Contracts/Edit.vue` -> modificar (2)
- `resources/js/Pages/Contracts/Create.vue` -> modificar (1)

## Especificação

### O que fazer

Em cada arquivo:

1. Localizar toda chamada a `toLocaleDateString`, `toLocaleString` e `toLocaleTimeString` aplicada a **data** e substituir pela função equivalente:
   - só o dia -> `formatarData`
   - dia com hora -> `formatarDataHora`
   - só a hora -> `formatarHora`
   - data por extenso -> `formatarDataExtensa`
2. Adicionar o import no `<script setup>`: `import { formatarData } from '@/utils/formatDate'` (importar apenas o que o arquivo usa).
3. Remover funções locais de formatação de data que existirem no arquivo, junto com as chamadas a elas.
4. Se o arquivo tiver `new Date(valor)` só para formatar, remover o `new Date` e passar o valor direto para o utilitário.

### Regras de negócio aplicáveis

- Não alterar layout, classe CSS, texto ou qualquer coisa fora da formatação de data.
- Não tocar em formatação de moeda: `toLocaleString('pt-BR', { minimumFractionDigits })` sobre número é valor em reais e fica como está.
- Validade de certificado e vigência de contrato aparecem em documento emitido. Qualquer mudança de dia exibido é regressão, não melhoria.

### Critérios de aceitação

- [ ] `grep -rn "toLocaleDateString\|toLocaleTimeString" resources/js/Pages/Certificates resources/js/Pages/Contracts` não devolve nada
- [ ] Todo arquivo alterado importa do `@/utils/formatDate`
- [ ] `npm run build` compila sem erro
- [ ] Nenhuma função local de formatação de data sobrou nos seis arquivos
