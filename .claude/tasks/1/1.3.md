# Task 1.3 - Agendamento das quatro rotinas com trava e registro

## Objetivo

Fazer as quatro rotinas existentes executarem automaticamente, sem sobreposição, gravando cada rodada em `scheduled_task_runs`.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `bootstrap/app.php` -> modificar (adicionar `withSchedule`)
- `app/Providers/AppServiceProvider.php` -> modificar (listeners de evento de comando) **ou** `app/Listeners/RegistraExecucaoAgendada.php` -> criar

## Contexto necessário (ler antes)

- `bootstrap/app.php` -> hoje não chama `withSchedule()`
- `routes/console.php` -> hoje só tem o `inspire` padrão
- `app/Console/Commands/` -> as quatro assinaturas: `certificates:update-status`, `payments:update-statuses`, `cash:sync-daily-balances`, `cash:create-missing-balances`
- `app/Models/ScheduledTaskRun.php` -> criado na Task 1.2

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

1. Em `bootstrap/app.php`, adicionar `->withSchedule(function (Schedule $schedule) { ... })` com:

   | Comando | Frequência | Horário |
   |---|---|---|
   | `certificates:update-status` | diário | 00:10 |
   | `payments:update-statuses` | diário | 00:20 |
   | `cash:sync-daily-balances` | diário | 00:30 |
   | `cash:create-missing-balances` | diário | 00:40 |

   Cada agendamento recebe:
   - `->timezone(config('app.business_timezone'))` para que "00:10" seja 00:10 em Brasília
   - `->withoutOverlapping(30)` (trava de 30 minutos)
   - `->runInBackground()` **não**: as rotinas são curtas e o registro depende do resultado

2. Registrar cada rodada em `scheduled_task_runs`. Use os hooks `->before()` e `->onSuccess()` / `->onFailure()` de cada agendamento, ou um listener dos eventos `ScheduledTaskStarting`, `ScheduledTaskFinished` e `ScheduledTaskFailed`. Prefira o listener: evita repetir o mesmo bloco quatro vezes.

   - No início: cria linha com `status = 'running'`, `started_at` e `task`
   - No fim: atualiza `finished_at`, `duration_ms`, `status` (`success` ou `failed`) e `output` com no máximo 2000 caracteres
   - Falha ao gravar o registro **nunca** pode derrubar a rotina: envolva a gravação em `try/catch` e mande o erro para o log

3. Não remover o `inspire` de `routes/console.php`, mas **remover o `->hourly()`** dele: é ruído que polui o log de agendamento.

### Regras de negócio aplicáveis

- Sem `schedule:run` no cron nada disso executa. A instrução de cron é a Task 1.4; esta task não a duplica.
- `withoutOverlapping` depende do cache configurado. Confirme que `CACHE_STORE` em produção não é `array` (que perderia a trava a cada request); se for, registre a observação no retorno da task.
- Ordem dos horários importa: o saldo diário depende dos status de pagamento já atualizados.

### Critérios de aceitação

- [ ] `php artisan schedule:list` mostra as quatro rotinas com o fuso `America/Sao_Paulo`
- [ ] `php artisan schedule:test` permite escolher e rodar cada uma delas
- [ ] Após uma execução, existe uma linha em `scheduled_task_runs` com `status = 'success'` e `finished_at` preenchido
- [ ] Comando que lança exceção grava `status = 'failed'` com a mensagem em `output`
- [ ] Erro ao gravar o registro não impede a rotina de terminar

## Teste esperado

- Comando: `php artisan schedule:list`
- Verificação manual: `php artisan schedule:test --name="certificates:update-status"` e conferir a linha criada em `scheduled_task_runs`
