# Task 1.1 - Fuso do negócio no backend e utilitário BusinessDate

## Objetivo

Definir `America/Sao_Paulo` como fuso do negócio em configuração e criar o utilitário que resolve "hoje" e "agora" nesse fuso, para que rotinas e comparações de vencimento parem de usar UTC.

## Tipo

backend-estrutura

## Arquivos a criar/modificar

- `config/app.php` -> modificar
- `.env.example` -> modificar
- `app/Support/BusinessDate.php` -> criar

## Contexto necessário (ler antes)

- `.claude/skills/datas-timezone/SKILL.md` -> regras de data e fuso do projeto
- `config/app.php` -> hoje usa `'timezone' => env('APP_TIMEZONE', 'UTC')`

## Skills necessárias

- `datas-timezone`
- `laravel-arquitetura`

## Especificação

### O que fazer

1. Em `config/app.php`, **manter** `'timezone' => env('APP_TIMEZONE', 'UTC')` intocado e adicionar logo abaixo:

   ```php
   'business_timezone' => env('APP_BUSINESS_TIMEZONE', 'America/Sao_Paulo'),
   ```

2. Em `.env.example`, adicionar `APP_BUSINESS_TIMEZONE=America/Sao_Paulo` junto das demais chaves `APP_`.

3. Criar `app/Support/BusinessDate.php`, classe final com métodos estáticos e nomes em português:

   - `fuso(): string` -> devolve `config('app.business_timezone')`
   - `hoje(): CarbonImmutable` -> data de hoje no fuso do negócio, com hora zerada (`startOfDay`)
   - `agora(): CarbonImmutable` -> instante atual convertido para o fuso do negócio
   - `paraFusoNegocio(mixed $valor): ?CarbonImmutable` -> converte um instante para o fuso do negócio; devolve `null` se `$valor` for `null`
   - `estaVencido(mixed $data): bool` -> `true` quando a data informada é **anterior** ao dia de hoje no fuso do negócio. Data igual a hoje **não** está vencida
   - `diaDe(mixed $valor): ?string` -> devolve `Y-m-d` do valor no fuso do negócio

### Regras de negócio aplicáveis

- `estaVencido()` compara **dia contra dia**, nunca instante contra instante. Um certificado que vence hoje não está vencido às 21h de Brasília.
- Campo `date` não sofre conversão de fuso: ao receber um `Carbon` já sem hora, apenas normalize para `startOfDay`, sem `setTimezone` que possa deslocar o dia.
- A classe é utilitário de infraestrutura, sem regra de domínio e sem acesso a banco.
- Não altere `APP_TIMEZONE`. O banco de produção tem `created_at`/`updated_at` gravados em UTC; mudar o fuso da aplicação reinterpretaria todo o histórico com 3 horas de diferença.

### Critérios de aceitação

- [ ] `config('app.business_timezone')` devolve `America/Sao_Paulo`
- [ ] `config('app.timezone')` continua `UTC`
- [ ] `BusinessDate::hoje()` devolve o dia correto quando o servidor está em UTC às 02h (que ainda é o dia anterior em Brasília)
- [ ] `BusinessDate::estaVencido(hoje)` devolve `false`
- [ ] `BusinessDate::estaVencido(ontem)` devolve `true`
- [ ] Nenhum uso de `now()` sem fuso dentro da classe
