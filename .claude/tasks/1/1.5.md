# Task 1.5 - Casts de data explícitos nos models sensíveis

## Objetivo

Declarar `date` para campo de dia e `datetime` para campo de instante nos models que sustentam validade, vencimento e execução, eliminando a ambiguidade que hoje produz erro de um dia.

## Tipo

backend-estrutura

- `app/Models/ServiceOrder.php` -> modificar

## Especificação

### O que fazer

Para cada model listado:

1. Levantar todas as colunas de data e hora da tabela com `php artisan db:table [tabela]`.
2. Classificar cada uma:
   - **Dia sem hora relevante** (vencimento, validade, data de execução, data agendada, data de pagamento, início e fim de contrato) -> cast `'date'`
   - **Instante** (hora de início e fim de execução, assinatura, timestamps) -> cast `'datetime'`
3. Declarar todos no `$casts` do model, sem deixar nenhum implícito.
4. Onde a coluna do banco for `datetime` mas o campo representar um dia, **não** altere a coluna nesta task: declare o cast como `date` e anote a divergência no retorno. Migration de tipo em tabela com dado de produção é outro deploy.

Campos que sabidamente entram, confira os nomes reais no schema:

- `WorkOrder`: data agendada, data de execução, `payment_status` relacionado a datas de vencimento
- `ServiceOrder`: data da OS e data de execução
- `Contract`: início, fim e data de renovação
- `PaymentDetail`: `payment_date` e `payment_due_date` como `date`

### Regras de negócio aplicáveis

- Campo `date` nunca recebe conversão de fuso. Converter campo de dia é justamente o que gera o erro de 24 horas.
- Só mexer em `$casts`. Nenhuma regra de negócio, nenhum accessor novo, nenhuma migration nesta task.
- Não renomeie coluna nem campo: telas e PDFs em produção dependem dos nomes atuais.

### Critérios de aceitação

- [ ] Todo campo de data dos cinco models tem cast declarado
- [ ] Nenhum campo de dia está como `datetime`
- [ ] `Certificate` continua com `execution_date` e `warranty` como `date`
- [ ] Nenhuma migration foi criada
- [ ] Divergências entre tipo do banco e cast estão listadas no retorno da task
