# Task 30.5 - Frontend: compromisso na Agenda

## Objetivo

Mostrar o compromisso avulso no calendário da Agenda, visualmente distinto
de uma ordem de serviço, e permitir criá-lo, concluí-lo, cancelá-lo e
promovê-lo para OS sem sair da tela.

## Tipo

frontend-pagina

## Arquivos a criar/modificar

- `resources/js/Components/Calendario/CalendarioAgenda.vue` -> modificar
- `resources/js/Pages/Agenda/Index.vue` -> modificar
- `resources/js/Components/ModalNovoCompromisso.vue` -> criar

## Contexto necessário (ler antes)

- `resources/js/Components/Calendario/CalendarioAgenda.vue` (arquivo
  inteiro) -> onde cada "visita" é renderizada (visão dia, semana, mês)
- `resources/js/Pages/Agenda/Index.vue` (arquivo inteiro) -> como busca
  `/agenda/dados`, como o painel lateral de detalhe funciona hoje para OS
- `resources/js/Components/EntregaDeEpiModal.vue` -> exemplo recente de

## Especificação

### O que fazer

1. Em `CalendarioAgenda.vue`, todo lugar que renderiza uma "visita" passa a
   checar `visita.tipo_item`. Quando for `'compromisso'`: cor de fundo/borda
   distinta da paleta já usada para OS (ex.: âmbar, mantendo o padrão de
   cores de status do design system do projeto, nunca cor inventada fora da
   paleta), e um rótulo curto do `tipo` do compromisso ("Orçamento",
   "Garantia", "Retorno", "Outro") visível no cartão.

2. Criar `resources/js/utils/compromisso.js` (ou arquivo equivalente já
   existente de utilitários) com um rotulador central, no padrão de
   `rotuloDeTipoDeEpi` (`resources/js/utils/epi.js`): `rotuloDeTipoDeCompromisso(tipo)`.

3. Botão "Novo compromisso" na `Agenda/Index.vue`, ao lado dos filtros já
   existentes, abre `ModalNovoCompromisso.vue`.

4. `ModalNovoCompromisso.vue`: formulário com `tipo` (select), `titulo`
   (obrigatório), busca de cliente (opcional, mesmo padrão de busca com
   debounce já usado no projeto), endereço (opcional: se o cliente tem
   endereço cadastrado, oferecer escolha; senão, campo de texto livre),
   técnico (opcional, select simples), `data`, `hora_inicio`/`hora_fim`
   (opcionais), `observacoes`. Envia `POST /compromissos`; no sucesso, fecha
   o modal e recarrega o período corrente da Agenda (mesmo padrão já usado
   depois de reagendar).

5. Ao clicar num item de compromisso no calendário, abrir o mesmo painel
   lateral de detalhe que a OS já usa, ramificando o conteúdo por
   `tipo_item`: para compromisso, mostrar tipo, título, cliente/endereço,
   técnico, observações, e três ações — "Concluir", "Cancelar" e "Promover
   para OS" (esta última desabilitada se o compromisso já tiver
   `work_order_id`). Cancelar usa modal de confirmação, nunca `confirm()`
   nativo.

### Regras de negócio aplicáveis

- Nunca `confirm()` nativo para cancelar ou excluir.
- Nenhuma formatação de data com `toLocaleDateString`: usar os utilitários
  de `resources/js/utils/formatDate.js`.
- Nenhuma regressão visual ou funcional no cartão de OS existente: a
  distinção de compromisso é aditiva.

### Critérios de aceitação

- [ ] Compromisso aparece no calendário (dia, semana e mês), visualmente
      distinto de OS
- [ ] Criar compromisso pela Agenda funciona sem recarregar a página inteira
- [ ] Concluir, cancelar e promover disponíveis a partir do item do
      compromisso
- [ ] OS existentes continuam renderizando exatamente como antes

## Teste esperado

- Comando: nenhum (sem suíte de teste JS no projeto)
- Verificação manual: abrir `/agenda`, criar um compromisso de cada tipo,
  conferir renderização nas três visões (dia, semana, mês), promover um
  compromisso para OS e conferir que a OS nasce com os dados certos
