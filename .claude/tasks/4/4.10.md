# Task 4.10 - Teste que detecta model de domínio sem a trait

## Objetivo

Criar o teste que percorre `app/Models/` e falha quando um model de domínio não usa `BelongsToCompany` ou quando uma tabela nova não foi classificada.

## Tipo

teste

## Arquivos a criar/modificar

- `tests/Feature/EscopoDeEmpresaTest.php` -> criar

## Contexto necessário (ler antes)

- `app/Support/DominioMultiempresa.php` -> as duas listas e o método `conferir()`
- `app/Models/Concerns/BelongsToCompany.php` -> trait a detectar
- `tests/Feature/` -> padrão dos testes do projeto

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

`EscopoDeEmpresaTest` com os casos:

1. **Model de domínio sem trait falha:** percorrer os arquivos de `app/Models/`, instanciar por reflexão, e para cada model cuja tabela está em `TABELAS_DE_DOMINIO`, exigir `BelongsToCompany` entre os traits usados (`class_uses_recursive`). A mensagem de falha nomeia o model e a tabela.
2. **Model fora do escopo não deve ter a trait:** o inverso, para pegar trait aplicada por engano em pivot ou em `Company`.
3. **Tabela não classificada falha:** `DominioMultiempresa::conferir()` devolve array vazio. Tabela nova criada por migration futura sem classificação derruba este teste, que é o objetivo.
4. **Coluna presente:** toda tabela de `TABELAS_DE_DOMINIO` tem a coluna `company_id` no schema.
5. **`company_id` fora do fillable:** nenhum model de domínio traz `company_id` em `$fillable`.
6. **Preenchimento automático:** dentro de `TenantAtual::comTenant(2, ...)`, criar um registro grava `company_id = 2` sem passá-lo explicitamente.

### Regras de negócio aplicáveis

- Este teste é a rede permanente do isolamento. Ele precisa falhar de forma barulhenta e com mensagem que diga exatamente qual model corrigir.
- O caso 3 é o que impede a regressão mais provável: alguém cria uma migration nova meses depois e esquece do `company_id`.
- Nenhum caso pode ser marcado como `skipped` ou `incomplete` para o teste ficar verde.

### Critérios de aceitação

- [ ] Os 6 casos passam no estado atual do código
- [ ] Remover a trait de um model qualquer faz o teste falhar, nomeando o model
- [ ] Criar uma tabela nova sem classificar faz o caso 3 falhar
- [ ] `php artisan test --filter=EscopoDeEmpresaTest` roda em menos de 10 segundos

## Teste esperado

- Comando: `php artisan test --filter=EscopoDeEmpresaTest`
- Verificação manual: comentar a trait em `app/Models/Client.php` e confirmar que o teste acusa

média - ~140 linhas | 1 arquivo
