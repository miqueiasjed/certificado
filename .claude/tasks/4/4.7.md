# Task 4.7 - Company::current() resolvendo pelo usuário autenticado

## Objetivo

Trocar `firstOrCreate(['id' => 1])` pela resolução do tenant do usuário logado, sem alterar o comportamento observado pelo cliente atual.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Models/Company.php` -> modificar
- `app/Models/User.php` -> modificar (relação `company()` e `company_id` no fillable)

## Contexto necessário (ler antes)

- `app/Models/Company.php` -> `current()` atual
- `app/Support/TenantAtual.php` -> resolvedor criado na Task 4.6
- `app/Services/BudgetService.php`, `app/Services/CertificateService.php`, `app/Services/WorkOrderService.php`, `app/Services/ContractService.php` -> as 7 chamadas de `Company::current()` no código

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

1. `Company::current()` passa a ser:
   ```php
   public static function current(): self
   {
       $id = TenantAtual::exigirId();
       return static::findOrFail($id);
   }
   ```
   O `firstOrCreate` sai: criar empresa por acidente em uma requisição de leitura era aceitável com um tenant e vira defeito grave com vários.

2. Conferir as 7 chamadas existentes. Todas passam a exigir tenant resolvido. Em contexto sem usuário autenticado (comando, seeder), a chamada agora lança exceção, o que é o comportamento desejado, e é a Task 4.9 que define o tenant nesses contextos.

3. Em `User`: adicionar `company_id` ao `$fillable` e a relação `company(): BelongsTo`.

4. `Company` recebe o campo `is_internal` (boolean) apenas se ele já existir do Plano 5; caso contrário, não antecipar. Anotar a dependência.

### Regras de negócio aplicáveis

- Com um único tenant, o resultado de `current()` é idêntico ao de antes: o usuário do cliente atual tem `company_id = 1`. Nenhuma diferença perceptível para ele, que é o entregável do plano.
- `exigirId()` lançando exceção é preferível a devolver 1 por padrão. Padrão silencioso é o caminho mais curto para um tenant enxergar dado de outro.
- Se alguma das 7 chamadas roda em contexto sem usuário (conferir cada uma), reportar qual e resolver na Task 4.9, não com fallback para 1.

### Critérios de aceitação

- [ ] `Company::current()` devolve a empresa do usuário logado
- [ ] Chamada sem tenant resolvido lança exceção com mensagem clara
- [ ] Nenhum `firstOrCreate` restou em `Company`
- [ ] As 7 chamadas existentes continuam funcionando em requisição HTTP autenticada
- [ ] `php artisan test` continua passando
- [ ] Gerar um PDF de certificado, um de OS e um de contrato produz o mesmo resultado de antes
