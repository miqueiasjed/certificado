# Task 14.2 - Service de enfileiramento com template e idempotência

## Objetivo

Concentrar em um Service a montagem da mensagem a partir do template, a checagem de preferência do cliente e o enfileiramento sem duplicar.

## Tipo

backend-logica

## Arquivos a criar/modificar

- `app/Services/NotificationService.php` -> criar
- `app/Support/EventosDeNotificacao.php` -> criar (catálogo)
- `app/Services/Notification/RenderizadorDeTemplate.php` -> criar

## Contexto necessário (ler antes)

- `app/Models/NotificationQueue.php` e `NotificationTemplate.php` -> criados na Task 14.1
- `app/Models/Client.php` -> preferências de canal
- `app/Support/RotinasAgendadas.php` -> como o projeto declara rotina
- `app/Support/BusinessDate.php` -> cálculo de véspera e de vencimento

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

1. `EventosDeNotificacao`: catálogo com os dez eventos do plano, cada um com chave, rótulo em português, destinatário padrão, canais aceitos e as variáveis disponíveis. Fonte única, consultada pela tela de templates e pelo seeder.

2. `RenderizadorDeTemplate::render(string $corpo, array $variaveis): string`: substitui `{{cliente_nome}}`, `{{os_numero}}`, `{{data_visita}}`, `{{empresa_nome}}` e as demais do catálogo. Variável desconhecida no template vira string vazia e é registrada, e não quebra o envio. Datas formatadas no fuso do negócio.

3. `NotificationService::enfileirar(string $evento, Model $referencia, array $opcoes = [])`:
   - resolve destinatário e destino;
   - checa a preferência do cliente e devolve `recusada` sem enfileirar quando o canal estiver desligado;
   - busca o template do tenant e cai no template padrão quando não houver;
   - monta a `chave_idempotencia` como `{evento}:{destinatario_tipo}:{destinatario_id}:{referencia_tipo}:{referencia_id}`;
   - grava na fila com `agendada_para` (imediato ou a data calculada);
   - trata a violação de unique como sucesso silencioso, porque significa que já está enfileirado.

4. `NotificationService::linkWhatsapp(NotificationQueue $item): string`: monta `https://wa.me/55DDDNUMERO?text=` com a mensagem codificada, para envio manual em um clique.

5. Nenhum envio acontece aqui. O Service só enfileira.

### Regras de negócio aplicáveis

- A chave de idempotência não leva timestamp. Levar o instante faria cada execução da rotina gerar uma chave nova, e o cliente receberia o mesmo lembrete todo dia.
- Cliente que recusou o canal não entra na fila, e o motivo fica registrado. Enfileirar e cancelar depois encheria a fila de lixo e confundiria o histórico.
- Sem template do tenant, usa o padrão. Evento sem nenhum template não pode falhar em silêncio: registra o erro e avisa a empresa.
- Telefone é normalizado para o formato internacional antes de montar o link `wa.me`. Número com máscara não abre a conversa.

### Critérios de aceitação

- [ ] Enfileirar o mesmo evento para a mesma referência duas vezes gera um item
- [ ] Cliente com o canal desligado não entra na fila
- [ ] Template do tenant tem prioridade sobre o padrão
- [ ] Variável desconhecida não quebra a renderização
- [ ] O link `wa.me` abre a conversa com a mensagem preenchida
- [ ] Datas renderizadas saem no fuso de Brasília
- [ ] Lembrete de véspera é agendado para a data certa
