# Task 11.5 - Substituição de dispositivo preservando o histórico do ponto

## Objetivo

Trocar um dispositivo danificado por um novo mantendo todo o histórico de eventos do ponto de instalação acessível.

## Tipo

backend-endpoint

## Arquivos a criar/modificar

- `app/Services/DeviceReplacementService.php` -> criar
- `app/Http/Requests/StoreDeviceReplacementRequest.php` -> criar
- `app/Http/Controllers/DeviceReplacementController.php` -> criar
- `routes/web.php` -> modificar

## Contexto necessário (ler antes)

- `app/Models/DeviceReplacement.php` -> criado na Task 11.1
- `app/Services/DeviceService.php` -> criação de dispositivo já existente
- `app/Models/WorkOrderDeviceEvent.php` -> histórico que precisa continuar acessível

## Skills necessárias

- `laravel-arquitetura`
- `datas-timezone`

## Especificação

### O que fazer

1. `DeviceReplacementService::substituir(Device $anterior, array $dados)`: em transação, cria o dispositivo novo copiando `address_id`, `label`, `number`, `bait_type_id` e `default_location_note` do anterior (com o que vier sobrescrito em `$dados`), gera o código público novo, marca o anterior com `situacao = substituido` e `active = false`, e grava a linha em `device_replacements`.

2. `DeviceReplacementService::historicoDoPonto(Device $device): Collection` sobe e desce a cadeia de substituições e devolve todos os dispositivos daquele ponto em ordem cronológica, do mais antigo ao atual. Usar para montar o histórico completo na tela.

3. `POST /dispositivos/{device}/substituir` com FormRequest validando `motivo` (obrigatório, na lista da Task 11.1), `substituido_em` (data, não pode ser futura no fuso do negócio), `observacao` (opcional, exigida quando o motivo for `outro`) e os campos opcionais do dispositivo novo.

4. Permissão `dispositivos.editar` na rota. `Device` chega por Model Binding, e o escopo da empresa já garante que não é de outro tenant.

5. `substituido_em` usa `BusinessDate::hoje()` como padrão e é comparado por dia no fuso do negócio.

### Regras de negócio aplicáveis

- Nenhum evento é movido para o dispositivo novo. Evento pertence ao dispositivo que o gerou, e mover falsificaria o histórico. A continuidade do ponto vem da cadeia em `device_replacements`.
- Substituir um dispositivo já substituído é recusado com mensagem clara: quem quer trocar de novo, substitui o dispositivo atual do ponto.
- O código público do dispositivo novo é novo, sempre. Reaproveitar o código do anterior faria a etiqueta velha, ainda colada em algum lugar, apontar para o registro errado.
- Substituição em massa não é escopo desta task.

### Critérios de aceitação

- [ ] Substituir cria o dispositivo novo com os dados copiados e código próprio
- [ ] O anterior fica com `situacao = substituido` e `active = false`
- [ ] Os eventos do anterior continuam ligados a ele
- [ ] `historicoDoPonto()` devolve a cadeia inteira em ordem, a partir de qualquer elo
- [ ] Substituir um dispositivo já substituído é recusado com 422
- [ ] Data futura em `substituido_em` é recusada
- [ ] Usuário sem `dispositivos.editar` recebe 403
