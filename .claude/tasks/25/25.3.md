# Task 25.3 - Rascunho de parecer e bloqueio de emissão não revisado

## Objetivo

Gerar o rascunho do parecer técnico a partir da OS e impedir que um documento saia com texto não revisado por uma pessoa.

## Tipo

backend-logica

- `app/Services/WorkOrderService.php` -> modificar (guarda de emissão)
- `app/Services/CertificateService.php` -> modificar (guarda de emissão)

## Especificação

### O que fazer

1. `ParecerService::gerarParaOs(WorkOrder $os, User $usuario): AiDraft`: monta o contexto, chama o provedor, grava o `AiDraft` com situação `gerado` e registra o uso. Recusa quando já existe rascunho `gerado` ou `em_revisao` para a mesma origem, apontando o existente.

2. O prompt de sistema instrui: parecer técnico objetivo, em português, baseado **apenas** nos dados fornecidos, sem inventar produto, praga ou quantidade que não esteja no contexto, e sem afirmar conclusão que o dado não sustenta. Quando faltar dado, o texto diz que falta, em vez de preencher.

3. `revisar(AiDraft $rascunho, string $texto, User $usuario)`: grava `conteudo_revisado`, marca `revisado`, registra quem revisou e quando, e grava na auditoria. `conteudo_gerado` nunca é alterado.

4. **Guarda de emissão**: `WorkOrderService` e `CertificateService` recusam emitir documento cujo parecer venha de um rascunho com situação diferente de `revisado`. A exceção traz mensagem em português explicando que o parecer precisa de revisão do responsável técnico.

5. `descartar(AiDraft $rascunho, User $usuario)`: marca `descartado` e libera a origem para nova geração.

6. `ParecerService::resumoDoPeriodo(MonitoringReport $relatorio, User $usuario)`: mesmo caminho, para o resumo do relatório do Plano 21, com a mesma exigência de revisão antes de publicar.

### Regras de negócio aplicáveis

- Laudo técnico tem responsabilidade profissional, e o responsável técnico assina o que sai. Publicação automática de parecer gerado por modelo transferiria ao cliente um risco que não é dele. Essa é a regra que não se negocia no plano.
- A guarda vive no Service de emissão, não na tela. Bloqueio só no frontend é bloqueio que a primeira rota nova fura.
- O texto gerado nunca é apagado: comparar gerado e revisado é o que prova a revisão humana.
- O prompt proíbe inventar dado. Parecer que afirma produto não aplicado é documento falso perante fiscalização.

### Critérios de aceitação

- [ ] Gerar produz o rascunho com situação `gerado`
- [ ] Segunda geração para a mesma origem é recusada, apontando o rascunho existente
- [ ] Revisar grava o texto revisado sem tocar no gerado
- [ ] Emitir documento com parecer não revisado lança exceção com mensagem em português
- [ ] Emitir com parecer revisado funciona
- [ ] Descartar libera nova geração
- [ ] Revisão aparece na auditoria com autor e instante
