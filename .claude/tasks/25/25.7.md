# Task 25.7 - Testes de isolamento, bloqueio e medição

## Objetivo

Provar que nenhum dado de um tenant alimenta o outro, que documento não sai sem revisão humana e que o uso é medido certo.

## Tipo

teste

## Arquivos a criar/modificar

- `tests/Feature/Ai/IsolamentoDeContextoTest.php` -> criar
- `tests/Feature/Ai/ParecerServiceTest.php` -> criar
- `tests/Feature/Ai/SugestaoDePrecoServiceTest.php` -> criar

## Contexto necessário (ler antes)

- `.claude/tasks/25/25.2.md` -> regras de isolamento e de cache
- `.claude/tasks/25/25.3.md` -> guarda de emissão
- `.claude/tasks/25/25.4.md` -> regras da sugestão
- `tests/Feature/EscopoDeEmpresaTest.php` -> padrão multiempresa

## Skills necessárias

- `laravel-arquitetura`
- `permissoes-e-multitenancy`

## Especificação

### O que fazer

1. `IsolamentoDeContextoTest`, com duas empresas cheias de dados:
   - o contexto montado para a empresa A **não contém nenhuma string** de dado da empresa B (percorrer o texto gerado procurando nomes de cliente, produtos e valores da outra empresa);
   - o mesmo para dados de outro cliente da própria empresa;
   - o prompt de sistema é idêntico entre duas chamadas (comparar as strings byte a byte, que é o que garante o cache);
   - falha do provedor grava `AiUsage` com `sucesso = false`;
   - a chave de API não aparece em nenhum log capturado no teste.

2. `ParecerServiceTest`:
   - gerar cria o rascunho com situação `gerado`;
   - segunda geração para a mesma origem é recusada;
   - **emitir documento com parecer não revisado lança exceção** (percorrer os métodos de emissão de OS e certificado e afirmar em cada um);
   - emitir com parecer revisado passa;
   - revisar não altera `conteudo_gerado`;
   - revisão fica na auditoria com autor e instante;
   - usuário sem `ia.revisar` recebe 403;
   - teto do plano atingido recusa a geração e **não impede** concluir OS nem emitir documento com parecer escrito à mão.

3. `SugestaoDePrecoServiceTest`:
   - com 10 referências, mediana e quartis conferem com o cálculo manual;
   - com 4, devolve histórico insuficiente sem valor;
   - orçamento de outra empresa nunca entra na busca;
   - a sugestão não altera o valor do orçamento;
   - o número não passa pelo provedor (afirmar que o provedor simulado não foi chamado para o cálculo).

4. Provedor sempre simulado. Nenhum teste faz chamada real.

### Regras de negócio aplicáveis

- O teste de isolamento é o mais importante do plano: um dado de outro tenant no contexto é vazamento com todas as consequências, e ele não aparece em revisão de código por leitura.
- O teste que percorre os métodos de emissão é o que impede uma rota nova, criada meses depois, publicar laudo não revisado.
- O teste de que o teto não afeta o resto protege a operação: limite de um recurso opcional nunca pode derrubar o essencial.

### Critérios de aceitação

- [ ] Os três arquivos passam
- [ ] O teste de ausência de dado de outro tenant no contexto está presente
- [ ] O teste que percorre os métodos de emissão está presente
- [ ] O teste de que o teto não afeta OS nem certificado está presente
- [ ] Nenhum teste chama o provedor real
- [ ] A suíte continua verde
